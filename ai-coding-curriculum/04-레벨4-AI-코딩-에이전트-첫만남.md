## ❓ 왜 배우나요?

- 지금까지는 AI가 **말로만** 도와줬어요. 에이전트는 **직접 파일을 읽고, 고치고, 명령을 실행**해요.
- 손이 생긴 만큼 **사고도 날 수 있어요.** 그래서 첫날부터 **권한(permission)과 샌드박스(sandbox)** 를 이해해야 해요.
- OpenAI best-practices [미러] 와 Cursor 문서 [미러] 모두 같은 원칙을 말해요: **"기본 권한으로 시작하고, 믿음이 쌓이면 조금씩 넓혀라."**

## 📚 핵심 개념

### 1. 세 가지 도구, 세 가지 모양

- 🧒 **비유:** 같은 도우미 로봇인데 **사는 집**이 달라요. 터미널에 사는 로봇, 코드 편집기에 사는 로봇, 인터넷(클라우드)에 사는 로봇.
- 📖 **정확히:**

| | Claude Code | OpenAI Codex | Cursor |
|---|---|---|---|
| 만든 곳 | Anthropic | OpenAI | Cursor |
| 기본 모양 | 터미널 에이전트 (CLI) | 터미널 에이전트 (CLI, Rust로 만듦) | AI 코드 편집기 (IDE) |
| 다른 모양 | VS Code 등 IDE 연결, GitHub Actions, Agent SDK | IDE 확장(VS Code/Cursor/Windsurf), 데스크톱 앱(`codex app`), 클라우드(`codex cloud`), GitHub Action | Cursor CLI(`agent`), Cloud Agents |
| 시작 명령 | `claude` | `codex` | 앱 실행 / CLI는 `agent` |
| 프로젝트 안내 쪽지 | `CLAUDE.md` (없으면 `AGENTS.md`도 읽음) | `AGENTS.md` | `.cursor/rules/*.mdc`, `AGENTS.md` |
| 로그인 | `/login` | ChatGPT 계정 또는 API 키 | Cursor 계정 (앱 안내를 따라요) |

### 2. 에이전트 루프 (Agentic loop)

- 🧒 **비유:** 요리사 로봇이 **① 냉장고 열어 재료 보기 → ② 요리하기 → ③ 맛보기**를 반복하는 거예요. 맛이 이상하면 다시 ①로!
- 📖 **정확히:** Claude Code 문서는 이걸 **정보 모으기(gather context) → 행동하기(take action) → 결과 확인(verify results)** 으로 설명해요. 일이 끝날 때까지 반복하고, **우리는 언제든 끼어들 수 있어요.**

```text
   ┌──────────────┐
   │ ① 정보 모으기  │  파일 읽기, 검색
   └──────┬───────┘
          ▼
   ┌──────────────┐
   │ ② 행동하기     │  파일 고치기, 명령 실행  ← 여기서 "허락"이 필요해요
   └──────┬───────┘
          ▼
   ┌──────────────┐
   │ ③ 확인하기     │  테스트·빌드 실행
   └──────┬───────┘
          └──── 아직이면 ①로 ────┘
```

### 3. 권한·승인 모드 (Permission / Approval mode)

- 🧒 **비유:** 도우미에게 주는 **허락 카드**예요. "읽기만 해도 돼", "고치는 건 물어보고 해", "다 알아서 해" 중 어떤 카드를 줄지 골라요.
- 📖 **정확히:** 도구마다 이름은 달라도 생각은 같아요.

**Claude Code 권한 모드** (`Shift+Tab`으로 바꿔요, `docs/permission-modes.md`)

| 모드 | 묻지 않고 하는 일 | 언제 쓰나요? |
|---|---|---|
| `default` (Manual) | 읽기만 | 모든 행동을 내가 보고 싶을 때 (**초보 추천**) |
| `acceptEdits` | 읽기 + 파일 수정 + 흔한 파일 명령 | 내가 검토하며 코드를 다듬을 때 |
| `plan` | 읽기 (고치지 않고 계획만) | 바꾸기 전에 살펴볼 때 |
| `auto` | 대부분 (뒤에서 분류기가 위험한 행동을 검사) | 긴 작업, 덜 묻게 하고 싶을 때 |
| `dontAsk` | 미리 허락한 도구만, 나머지는 거절 | 잠가 둔 자동화(CI) |
| `bypassPermissions` | **전부** | **격리된 컨테이너/VM에서만** |

> 💡 문서 기준으로 최근 버전의 터미널 세션은 `auto`로 시작해요 (v2.1.283+). 처음 배울 때는 **화면 아래 상태 표시줄에서 모드를 꼭 확인**하고, `claude --permission-mode default`로 시작하거나 `Shift+Tab`으로 바꿔서 연습하세요.

**Codex: 샌드박스 × 승인 정책** (`codex-rs/protocol` 소스)

| 샌드박스 (`-s`) | 뜻 |
|---|---|
| `read-only` | 기본값. 읽기만 |
| `workspace-write` | 작업 폴더 안에서만 고치기. 네트워크는 기본 차단 |
| `danger-full-access` | 샌드박스 없음 ⚠️ |

| 승인 정책 (`-a`) | 뜻 |
|---|---|
| `untrusted` | 믿을 수 있는 명령 말고는 다 물어봐요 |
| `on-request` | 기본값. 필요할 때 모델이 물어봐요 |
| `never` | 절대 안 물어봐요 |

**Cursor 실행 모드** (Settings > Agents > Approvals & Execution) [미러]

| 모드 | 묻지 않고 하는 일 |
|---|---|
| **Auto-review** (대부분에게 권장) | 허용 목록은 바로 실행, 나머지는 가능하면 샌드박스에서 실행, 안 되면 분류기가 검토 |
| **Allowlist** | 허용 목록에 있는 것만 자동 실행 |
| **Run Everything** | 전부 ⚠️ |

> Cursor 문서는 "**Auto-review는 보안 경계가 아니다**"라고 분명히 말해요. 분류기도 틀릴 수 있어요.

### 4. 샌드박스 (Sandbox)

- 🧒 **비유:** **모래 놀이터**예요. 그 안에서는 마음껏 놀아도 되지만, 울타리 밖(내 사진 폴더, 인터넷)은 못 나가요.
- 📖 **정확히:** 운영체제 수준에서 에이전트가 건드릴 수 있는 **폴더와 네트워크를 제한**하는 장치예요. Claude Code는 `/sandbox`, Codex는 `-s`, Cursor CLI는 `/sandbox` 또는 `--sandbox enabled|disabled`로 다뤄요.
- ⚠️ "다 허락" 모드(Claude `--dangerously-skip-permissions`, Codex `--yolo`, Cursor Run Everything)는 **외부와 격리된 컨테이너나 VM에서만** 써요. MIT Missing Semester도 "yolo 모드는 안전하지 않다. VM이나 컨테이너 같은 격리 환경에서 돌려라"라고 해요. Codex 소스 주석에는 **"EXTREMELY DANGEROUS"** 라고 적혀 있어요.

### 5. 체크포인트 vs git

- 🧒 **비유:** 체크포인트는 **연필로 쓴 임시 메모**, git 커밋은 **볼펜으로 쓴 공식 일기**예요.
- 📖 **정확히:**

| 도구 | 되돌리기 기능 | 한계 |
|---|---|---|
| Claude Code | `Esc Esc` 또는 `/rewind` (코드·대화·둘 다) | Bash 명령으로 바뀐 파일은 추적 안 함 |
| Cursor | Checkpoints (큰 변경 전 자동 스냅샷) | 내 컴퓨터에만, git과 별개 |
| Codex | `/diff`로 변경 확인 | 되돌리기는 git으로 (`/undo`는 현재 소스에서 확인 못 함) |

→ **영구 기록은 언제나 git.** 에이전트 작업 전에 `git status`가 깨끗한지 확인하고, 잘되면 커밋해요.

### 실습 2. 첫 대화: 읽기만 하기 (30분)

**Claude Code**
```bash
cd ~/ai-practice/git-practice

```
안에서:
```text
/help
이 폴더에 어떤 파일이 있고, 각각 무슨 일을 하는지 초보자에게 설명해 줘. 아무것도 고치지 마.
```
- `@calc.py`처럼 `@`로 파일을 가리킬 수 있어요.
- `!ls`처럼 `!`를 붙이면 내가 직접 셸 명령을 실행해요.
- 답이 길게 엉뚱한 쪽으로 가면 `Esc`로 멈춰요. (지금까지 한 일은 남아요.)
- 나갈 때는 `Ctrl+D` 또는 `Ctrl+C`.

**Codex**
```bash
codex -s read-only
```
```text
이 폴더의 코드를 설명하고, 처음 읽어야 할 파일을 알려 줘.
```
- `/status`로 현재 설정(샌드박스·승인)을 확인해요.

**Cursor**
- 폴더를 열고, 에이전트 창(Cmd+I)을 열어요 [미러]. 모드를 **Ask**(읽기 전용)로 바꾸고 같은 질문을 해요.

✅ **Done when:** 에이전트가 파일을 하나도 고치지 않았고(`git status` 깨끗), 설명을 받았어요.

### 실습 3. 코드베이스 투어 + 검증 (45분)

진짜 오픈소스를 둘러봐요. 약 100줄짜리 핵심 루프를 가진 작은 에이전트 프로젝트예요.

```bash
cd ~/ai-practice

```

읽기 전용 모드에서 물어봐요.
```text
이 코드베이스를 설명해 줘.

2) 핵심 모듈 3개와 각각의 역할

```

그다음 **내가 직접** 그 파일들을 열어 맞는지 확인해요.

✅ **Done when:** 에이전트 답에서 틀린 곳을 1개 이상 찾았거나, 모두 맞다는 것을 파일을 열어 확인했어요. (OpenAI 쪽 학습 순서 2단계 과제)

### 실습 4. 허락 카드 실험 (45분)

연습 저장소(`git-practice`)에서, 모드를 바꿔 가며 같은 부탁을 해요.

```text
calc.py에 "곱하기 결과가 100보다 크면 '큰 수!'를 출력"하는 기능을 추가해 줘.
```

| 모드 | 무엇을 물어봤나요? | 무엇이 막혔나요? |
|---|---|---|
| Claude `default` / Codex `read-only` / Cursor Ask | | |
| Claude `acceptEdits` / Codex `-s workspace-write -a on-request` / Cursor Allowlist | | |
| Claude `plan` / Codex `/plan` / Cursor Plan | | |

실험이 끝날 때마다 `git diff`로 확인하고, `git restore .`로 되돌려요.

✅ **Done when:** 모드별 "묻는 행동 / 막힌 행동" 표를 완성했어요.

### 실습 5. 안전한 개선 3가지 → 하나 고르기 (30분)

```text
이 저장소에서 안전하게 할 수 있는 작은 개선 3가지를 제안해 줘.
각각 무엇을, 왜, 어떤 파일을 바꾸는지 적고, 내가 고를 때까지 아무것도 고치지 말고 기다려.
```

1. 하나를 골라 진행시켜요.
2. **`git diff`를 한 줄씩 읽어요.** (Codex는 `/diff`, Cursor는 리뷰 화면)
3. 마음에 들면 `git commit`, 아니면 `git restore .`

✅ **Done when:** `git log`에 커밋 1개가 남았거나, `git status`가 깨끗하게 돌아왔어요.

## ⚠️ 흔한 실수

| 실수 | 이렇게 해요 |
|---|---|
| 중요한 파일이 있는 폴더(홈 전체 등)에서 실행 | **연습 저장소 폴더 안에서만** 실행 |
| 처음부터 "다 허락" 모드 | 기본 권한에서 시작, 천천히 넓히기 (OpenAI·Cursor 공통 권고) |
| 승인 창을 읽지 않고 계속 "예" | 명령을 읽고 모르면 "이 명령이 무슨 일을 하는지 설명해 줘"라고 묻기 |
| 에이전트의 "다 했어요"를 믿음 | `git diff`와 실행 결과로 확인 |
| 세 도구를 동시에 깊게 배우기 | 하나를 주력으로, 나머지는 비교용 |
| 블로그에서 본 옛날 플래그 사용 | 예: Codex `--full-auto`는 현재 소스에서 찾을 수 없어요 (예전 방식). `--help`로 확인 |
