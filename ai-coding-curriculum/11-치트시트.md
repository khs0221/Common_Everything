## 1. 터미널

| 명령 | 🧒 뜻 | 예 |
|---|---|---|
| `pwd` | 지금 내가 있는 곳 주소 | `pwd` |
| `ls` | 이 폴더에 뭐가 있나 | `ls` |
| `cd 폴더` | 폴더로 들어가기 | `cd ai-practice` |
| `cd ..` | 한 칸 위로 | `cd ..` |
| `cd ~` | 내 집(홈 폴더)으로 | `cd ~` |
| `mkdir 이름` | 새 폴더 만들기 | `mkdir todo-app` |
| `echo "글" > 파일` | 글을 파일로 저장 (덮어쓰기) | `echo "안녕" > hello.txt` |
| `cat 파일` | 파일 내용 보기 | `cat hello.txt` |
| `cp A B` | 복사 | `cp hello.txt copy.txt` |
| `mv A B` | 이동 / 이름 바꾸기 | `mv copy.txt hi.txt` |
| `rm 파일` | ⚠️ 삭제 (휴지통 없음!) | 연습 폴더에서만 |
| `명령 --help` | 사용법 보기 | `ls --help` |
| `A \| B` | A의 결과를 B에게 넘기기 (파이프) | `cat error.log \| claude -p "무슨 문제야?"` |
| `Ctrl+C` | 실행 중인 것 멈추기 | |
| `↑` / `Tab` | 이전 명령 / 자동 완성 | |

**파이썬 환경**

| 명령 | 뜻 |
|---|---|
| `python3 파일.py` | 파이썬 파일 실행 |

| `curl 주소` | 터미널에서 웹 주소 요청하기 |

## 2. git · GitHub

| 상황 | 명령 | 🧒 비유 |
|---|---|---|
| 처음 설정 | `git config --global user.name "이름"` · `user.email` | 세이브 파일에 이름 쓰기 |
| 저장소 시작 | `git init` | 세이브 기능 켜기 |
| 상태 보기 | `git status` | 지금 뭐가 바뀌었나? |
| 무대에 올리기 | `git add 파일` | 사진 찍을 친구 세우기 |
| 세이브 | `git commit -m "메시지"` | 찰칵! 세이브 포인트 |
| 고친 파일 한 번에 세이브 | `git commit -am "메시지"` | (이미 추적 중인 파일만) |
| 기록 보기 | `git log --oneline --graph` | 세이브 목록 |
| 바뀐 내용 보기 | `git diff` · `git diff --staged` · `git show` | 틀린 그림 찾기 |
| 새 평행 세계 | `git switch -c 브랜치` | 세이브 슬롯 복사 |
| 세계 이동 | `git switch main` | |
| 합치기 | `git merge 브랜치` | |
| 작업 버리기 | `git restore 파일` | 아직 세이브 안 한 걸 되돌리기 |
| 세이브 취소 기록 | `git revert 커밋` | "취소했음" 세이브를 새로 만들기 |
| 올리기 | `git push -u origin 브랜치` | 클라우드 저장 |
| 받기 | `git pull` | |
| PR 열기 | GitHub 웹 **Compare & pull request** 또는 `gh pr create` | "합쳐도 될까요?" 요청서 |
| 평행 작업실 | `git worktree add ../폴더 -b 브랜치` · `git worktree list` · `git worktree remove 폴더` | 같은 레고를 다른 방에 한 벌 더 |

> 🛡️ **에이전트 작업 규칙:** 시작 전 `git status` 깨끗하게 → 작업 → `git diff` 읽기 → 테스트 → 커밋. 되돌릴 때는 AI 기능보다 **git**을 믿어요.

## 4. Codex

### 설치와 시작

| 할 일 | 명령 |
|---|---|
| 설치 | `npm install -g @openai/codex` · `brew install --cask codex` · `curl -fsSL https://chatgpt.com/codex/install.sh \| sh` |
| 시작 | `codex` (ChatGPT 계정 또는 API 키로 로그인) |
| 샌드박스 지정 | `-s read-only` · `-s workspace-write` · `-s danger-full-access` |
| 승인 정책 지정 | `-a untrusted` · `-a on-request` · `-a never` |
| 모델 · 프로필 | `-m 모델` · `-p 프로필` |
| 폴더 지정 · 쓰기 폴더 추가 | `-C 폴더` · `--add-dir 폴더` |
| worktree에서 | `--worktree` |
| 대화 이어서 · 분기 | `codex resume` · `codex fork` |
| 클라우드 작업 | `codex cloud` · 결과 가져오기 `codex apply` |
| MCP 관리 | `codex mcp list\|get\|add\|remove\|login\|logout` |
| ⚠️ 위험 | `--dangerously-bypass-approvals-and-sandbox` (= `--yolo`) — 이미 격리된 환경에서만 |
| (예전 방식) | `--full-auto` — 현재 소스에서 찾지 못함. 쓰지 마세요 |

**샌드박스 × 승인 정책**

| 샌드박스 | 뜻 | 승인 정책 | 뜻 |
|---|---|---|---|
| `read-only` (기본) | 읽기만 | `untrusted` | 신뢰된 명령 외엔 다 물어봄 |
| `workspace-write` | 작업 폴더 안 편집 (네트워크 기본 차단) | `on-request` (기본) | 필요할 때 모델이 물어봄 |
| `danger-full-access` | 제한 없음 ⚠️ | `never` | 절대 안 물어봄 (실패는 모델에게) |

## 5. Cursor

> Cursor는 대부분 **[미러]** 문서로 확인했어요. 메뉴 이름과 단축키는 버전마다 달라질 수 있어요.

| 할 일 | 방법 |
|---|---|
| 에이전트 창 | `Cmd+I` [미러] |
| 인라인 편집 | `Cmd/Ctrl+K` |
| 모드 바꾸기 | **Agent**(기본, 모든 도구) / **Plan**(`Shift+Tab`) / **Ask**(읽기 전용) |
| 맥락 붙이기 | `@파일` · `@폴더` · `@Terminals` · `@Chats` · `@Commit` · `@Branch` · `@Browser` |
| 메시지 보내기 | `Enter` = Queue(지금 일 끝나고), **Send now** 또는 `Enter` 두 번 = Steer |
| 체크포인트 | 큰 변경 전에 자동 저장. 로컬 저장이고 **git과 별개** |
| 리뷰 | `/agent-review` — **Quick**(빠름·저렴) / **Deep**(느림·꼼꼼). 규칙은 `BUGBOT.md` |
| 만들기 명령 | `/create-rule` · `/create-skill` · `/create-subagent` · `/create-hook` |
| 기타 명령 | `/babysit`(PR 피드백·CI 대응) · `/loop` · `/automate` |
| 실행 권한 | Settings > Agents > Approvals & Execution — **Auto-review** 권장 ("보안 경계는 아님") |

**Cursor CLI [미러]**

| 할 일 | 명령 |
|---|---|
| 설치 | `curl https://cursor.com/install -fsS \| bash` |
| 시작 | `agent` |
| 한 번 실행 | `agent -p "질문" --output-format text` |
| 모드 | `--mode=plan` · `--mode=ask` (또는 `/plan`, `/ask`) |
| 세션 | `agent ls` · `agent resume` · `--continue` · `--resume=<id>` |
| 클라우드로 넘기기 | 메시지 앞에 `&` |

**파일 위치 [미러]**

| 무엇 | 어디 |
|---|---|
| 프로젝트 규칙 | `.cursor/rules/*.mdc` (규칙 하나 500줄 이하) |
| 단순 안내 쪽지 | `AGENTS.md` (하위 폴더 중첩 가능, 하위가 우선) |
| 스킬 | `.cursor/skills/` · `.agents/skills/` (`.claude/skills/`도 읽음) |
| 서브에이전트 | `.cursor/agents/*.md` |
| worktree 준비 | `.cursor/worktrees.json` (`setup-worktree`) |
| 권한 | `~/.cursor/permissions.json` |
| (예전 방식, 확인 필요) | `.cursorrules` 단일 파일 — 현재 문서에서 확인 못 함. `.mdc`나 AGENTS.md를 쓰세요 |

## 7. 프롬프트 템플릿

### 7-1. 기본 4요소 (모든 부탁의 뼈대)

```text
목표: [무엇을 만들거나 고칠지 한 문장]
맥락: [관련 파일 @파일, 에러 메시지, 참고할 기존 코드]
제약: [쓰면 안 되는 것, 지켜야 할 규칙, 건드리면 안 되는 파일]
완료 기준: [테스트 통과, 이런 입력에 이런 출력, 증거로 보여 줄 것]
```

### 7-2. 선생님 모드 (🔴 배울 때)

```text
나는 [파이썬 반복문]을 배우는 초보야. 정답 코드를 바로 주지 마.
힌트를 한 단계씩 주고, 내가 직접 코드를 쓰면 무엇이 틀렸는지 질문으로 알려 줘.
마지막에 내가 이해했는지 확인하는 문제 2개를 내 줘.
```

### 7-3. 에러 설명 받기

```text
아래 에러가 났어. 고치지 말고 먼저 설명해 줘.
1) 에러 메시지의 각 줄이 무슨 뜻인지  2) 가능한 원인 3가지  3) 확인하는 방법
[traceback 붙여 넣기]
```

### 7-4. 버그 고치기 (테스트 먼저)

```text
[증상: 세션이 만료된 뒤 로그인이 실패해요]
[어디: src/auth/ 의 토큰 갱신 부분]을 살펴보고,
이 문제를 재현하는 실패하는 테스트를 먼저 쓰고, 그다음 고쳐 줘.
근본 원인을 고치고 에러를 숨기지 마. 테스트 명령과 결과를 보여 줘.
```

### 7-5. TDD

```text
TDD로 할 거야. 가짜 구현을 만들지 마.
1) [validate_email] 테스트를 먼저 써 줘: user@example.com → True, invalid → False, user@.com → False
2) 테스트를 실행해서 실패하는 걸 보여 주고 멈춰. 아직 구현하지 마.
(내가 테스트를 커밋한 뒤)
3) 테스트를 고치지 말고, 테스트가 통과할 때까지 구현해 줘.
```

### 7-6. 탐색 → 계획 (계획 모드에서)

```text
[src/auth]를 읽고 [세션과 로그인 처리 방식]을 이해해 줘. 아직 아무것도 고치지 마.
[구글 로그인 추가]를 하고 싶어. 어떤 파일을 바꿔야 해? 계획을 세워 줘.
계획에는 바꿀 파일, 순서, 테스트 계획, 가정을 넣어 줘.
```

### 7-7. 인터뷰 → 명세

```text
[할 일 앱]을 만들고 싶어. 명세를 쓸 수 있을 때까지 나를 인터뷰해 줘.
한 번에 질문 하나씩. 다 끝나면 SPEC.md로 저장해 줘.
```
→ 그다음 **새 세션**에서: `SPEC.md를 읽고 구현 계획을 세워 줘.`

### 7-8. 코드베이스 둘러보기

```text
이 코드베이스를 처음 보는 사람에게 설명해 줘. 파일은 고치지 마.
1) 무엇을 하는 프로그램인지  2) 시작점(진입점) 파일  3) 중요한 폴더 3개
4) 테스트 실행 방법  5) 먼저 읽을 파일 순서
```

### 7-9. 리뷰 (새 세션에서)

```text
커밋되지 않은 변경을 리뷰해 줘.
이번 변경 때문에 새로 생긴, 실제로 고칠 수 있는 버그만 지적해. 스타일 지적은 빼.
각 지적마다: 파일:줄 / 문제가 생기는 상황 / 고치는 방향. 짧게.
```

### 7-10. 보안 점검

```text
이 저장소의 보안 문제를 찾아 줘. 고치지는 마.
비밀 키 하드코딩, 입력 검증 누락, 위험한 셸 명령 실행, .env 노출을 확인하고
각각 파일:줄, 위험도, 이유를 표로 정리해 줘.
```

### 7-11. 프롬프트 고쳐 받기 (메타 프롬프트)

```text
아래 프롬프트를 AI 코딩 에이전트가 더 정확히 따를 수 있게 고쳐 줘.
목표 / 맥락 / 제약 / 완료 기준이 빠졌으면 무엇이 빠졌는지 먼저 알려 줘.
[내 프롬프트]
```

### 7-12. 정리하고 다시 시작 (두 번 고쳐도 안 될 때)

```text
지금까지 시도한 것, 실패한 이유, 알게 된 사실을 5줄로 요약해 줘.
```
→ 요약을 복사 → `/clear`(또는 새 채팅) → 요약 + **더 구체적인 프롬프트**로 다시 시작

### 7-13. 긴 목표 (`/goal`)

```text
/goal tests/ 폴더의 모든 테스트가 통과하고 린트가 깨끗하다.
src/ 안의 파일만 고쳐. 테스트 파일은 고치지 마.
같은 에러로 세 번 실패하면 멈추고 무엇이 막혔는지 알려 줘.
```

# Commands

# Commands

## Cursor 규칙(.mdc) 템플릿

`.cursor/rules/` 안에 `.mdc` 파일로 만들어요. **frontmatter가 언제 적용될지 정해요.** [미러]

| 적용 방식 | frontmatter |
|---|---|
| 항상 | `alwaysApply: true` |
| 에이전트가 판단 | `description`만 |
| 특정 파일에서만 | `globs: tests/**/*.py` |
| 내가 부를 때만 | 채팅에서 `@규칙이름` |

공식 예시 (cursor/plugins `no-inline-imports.mdc`):
```markdown
---
description: Keep imports at top of file and avoid inline imports
alwaysApply: true
---
# No inline imports
Always place imports at the top of the module. ...
```

우리 todo-app용 예시:
```markdown
---
description: pytest 테스트 작성 규칙
globs: tests/**/*.py
alwaysApply: false
---
# 테스트 규칙
- 테스트 이름은 test_무엇을_어떤상황에서_어떻게 형식
- 진짜 data/ 파일 대신 임시 파일을 쓴다
- 실패하는 테스트를 지우거나 약하게 바꾸지 않는다
```
