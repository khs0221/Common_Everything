## 📚 핵심 개념

### 1. "부탁"과 "규칙"은 달라요 (비결정적 vs 결정적)

- 🧒 **비유:** "숙제하고 놀아"라는 **엄마의 부탁**은 가끔 잊어요. 하지만 **현관 잠금장치**는 절대 안 잊어요.
- 📖 **정확히:** (Claude Code `best-practices.md`)

| 종류 | 무엇 | 지켜질까? |
|---|---|---|
| **비결정적 (모델이 판단)** | 프롬프트, CLAUDE.md/AGENTS.md, rules, skills | 대부분 지키지만 **가끔 놓쳐요** |
| **결정적 (프로그램이 강제)** | hooks, deny 규칙, 관리 설정, `--max-turns`·`--max-budget-usd` | **항상** 적용돼요 |

**어떤 도구를 언제 쓰나요?** (Claude `features-overview.md`, OpenAI·Cursor 문서 종합)

| 하고 싶은 일 | 쓸 도구 | 비유 |
|---|---|---|
| 항상 알아야 하는 짧은 사실 | CLAUDE.md / AGENTS.md / rules | 냉장고에 붙인 쪽지 |
| 가끔 필요한 긴 절차 | **Skills** | 필요할 때 꺼내는 레시피 카드 |
| 절대 어기면 안 되는 규칙 | **Hooks**, deny 규칙 | 자동 잠금장치 |
| 시끄러운 곁일, 새로운 눈, 병렬 작업 | **Subagents** | 따로 일하는 조수 |
| 외부 시스템 연결 | **MCP** (CLI가 있으면 CLI 먼저) | 새 연장 |
| 위 묶음을 나눠 주기 | **Plugins** | 도구 상자 세트 |

### 2. 규칙 심화 (경로별 규칙, 중첩 쪽지)

- 🧒 **비유:** 집 전체 규칙 말고, **"부엌에서는 이것", "욕실에서는 저것"** 처럼 방마다 규칙을 붙여요.
- 📖 **정확히:**
  - **Claude Code:** `.claude/rules/*.md` 파일 머리말(frontmatter)에 `paths:` glob을 쓰면 그 경로를 다룰 때만 적용돼요. CLAUDE.md에서 `@path/to/file`로 다른 파일을 불러올 수 있어요. `/doctor prompt-audit`은 오래되거나 서로 부딪히는 줄을 찾아 줘요.
  - **Cursor 규칙(.mdc) 4가지 적용 방식** [미러]

| 적용 방식 | 머리말 | 언제 적용? |
|---|---|---|
| 항상 (Always Apply) | `alwaysApply: true` | 매번 |
| 똑똑하게 (Apply Intelligently) | `description`만 | 에이전트가 설명을 보고 판단 |
| 특정 파일 (Specific Files) | `globs: **/*.py` | 그 파일을 다룰 때 |
| 직접 (Manually) | (없음) | 채팅에서 `@규칙이름` |

  - **중첩 AGENTS.md:** Codex와 Cursor 모두 하위 폴더의 AGENTS.md를 읽고, **더 가까운(구체적인) 쪽이 우선**이에요.

### 3. Skills와 슬래시 명령 (레시피 카드)

- 🧒 **비유:** "생일 케이크 만들기" 같은 긴 레시피를 **카드로 만들어 서랍에** 넣어 둬요. 평소엔 카드 **제목만** 보이고, 필요할 때 꺼내 읽어요.
- 📖 **정확히:** Claude, Codex, Cursor 모두 **`이름/SKILL.md`** 모양의 Agent Skills 형식을 써요.
  - 머리말: `name`, `description`. **description은 "언제 이 skill을 쓸지" 알려 주는 방아쇠 문장**이에요.
  - 평소엔 이름과 설명만 컨텍스트에 올라가고, 쓸 때 본문이 올라가요 (컨텍스트 절약).
  - 선택 폴더: `scripts/`, `references/`, `assets/`

| | Claude Code | Codex [미러 포함] | Cursor [미러] |
|---|---|---|---|
| 프로젝트 위치 | `.claude/skills/<이름>/SKILL.md` | `.agents/skills` | `.agents/skills/`, `.cursor/skills/` (`.claude/skills/`, `.codex/skills/`도 호환으로 읽음) |
| 개인 위치 | `~/.claude/skills/<이름>/SKILL.md` | `$HOME/.agents/skills` | `~/.agents/skills/`, `~/.cursor/skills/` |
| 부르기 | `/이름` | `$이름`, 목록 `/skills` | `/이름` |
| 만들기 도우미 | (플러그인 `skill-creator`) | `$skill-creator` | `/create-skill` |

  - **Claude Code에서는 커스텀 슬래시 명령이 skills로 합쳐졌어요.** `.claude/commands/deploy.md`와 `.claude/skills/deploy/SKILL.md` 둘 다 `/deploy`를 만들어요. `disable-model-invocation: true`를 쓰면 **나만** 부를 수 있어요 (모델이 알아서 못 씀).

### 4. Hooks (자동 경보기)

- 🧒 **비유:** 문이 열리면 **자동으로 울리는 경보기**예요. 도우미가 잊어도 기계가 알아서 해요.
- 📖 **정확히:** (Claude Code `hooks.md`) 특정 **사건(event)** 이 생길 때 내 명령을 자동 실행해요. `settings.json`의 `"hooks"`에 적어요.

| 사건 | 언제? | 예시 용도 |
|---|---|---|
| `PreToolUse` | 도구 쓰기 **전** (막을 수 있음) | 특정 폴더 수정 금지 |
| `PostToolUse` | 도구 쓴 **후** | 파일 고치면 자동 정리(포매터) |
| `Stop` | 에이전트가 "끝!" 하려 할 때 | 테스트 통과 안 하면 다시 일하게 |
| `SessionStart`, `UserPromptSubmit`, `Notification`, `SessionEnd` 등 | | |

  - **종료 코드 2** = 막기. 에러 출력(stderr)이 Claude에게 전달돼요. 종료 코드 0 + 출력 없음 = 그냥 통과.
  - Stop hook이 **8번 연속** 막으면 Claude Code가 다음 막기를 무시하고 턴을 끝내요 (무한 반복 방지).
  - Cursor에도 hooks가 있어요 (cursor/cookbook `hooks/`: 감사 로그, 민감한 프롬프트 차단, `/create-hook`).

### 5. Subagents (따로 일하는 조수)

- 🧒 **비유:** 반장이 "너는 도서관 가서 자료 조사만 해 와" 하고 **조수를 보내요.** 조수는 **깨끗한 책상**에서 일하고, **요약만** 가져와요.
- 📖 **정확히:**
  - 각 subagent는 **자기만의 컨텍스트 창**을 갖고 깨끗하게 시작해요. 그래서 필요한 정보를 **부탁할 때 다 담아 줘야** 해요 (Cursor 문서).
  - Claude Code: `.claude/agents/*.md`(프로젝트), `~/.claude/agents/`(개인). 머리말 `name`, `description`(필수), `tools`, `model` 등. 내장 Explore, Plan, general-purpose. `/agents`로 관리.
  - Cursor [미러]: `.cursor/agents/*.md`, 내장 **Explore / Bash / Browser**, `/create-subagent`.
  - Codex: `/agents` 명령. 메인 대화가 지저분해지는 것(context pollution)을 막는 데 좋아요 [미러].
  - ⚠️ **subagent도 토큰(비용)을 써요.** "더 똑똑한 답"이 아니라 **병렬 작업이나 새로운 눈**을 주는 거예요. 간단한 일은 가벼운 모델(Claude는 `model: haiku`)로.

### 6. MCP와 플러그인 (새 연장, 도구 세트)

- 🧒 **비유:** MCP는 도우미 손에 끼우는 **만능 어댑터**예요. 어댑터만 있으면 Notion, 브라우저, 데이터베이스 같은 새 연장을 꽂을 수 있어요.
- 📖 **정확히:** **MCP(Model Context Protocol)** 는 에이전트를 외부 도구·데이터에 연결하는 표준 방식이에요.

| | 추가 | 관리 | 설정 파일 |
|---|---|---|---|
| Claude Code | `claude mcp add --transport http 이름 URL` / `claude mcp add --transport stdio 이름 -- 명령` | `/mcp` | 팀 공유는 `.mcp.json` |
| Codex | `codex mcp add` (자세한 사용법은 `codex mcp add --help`) | `codex mcp list`, `/mcp` | `~/.codex/config.toml`의 `[mcp_servers.<이름>]` |
| Cursor | 설정 화면 / 문서 `mcp.md` (확인 필요) | | |

  - **CLI가 있으면 CLI가 먼저예요.** `gh`가 설치·로그인돼 있으면 Claude는 추가 설정 없이 PR을 다뤄요.
  - **안 쓰는 MCP 서버는 꺼요.** 도구 이름들이 컨텍스트를 차지해요.
  - **플러그인(plugin)** 은 skills + subagents + hooks + MCP 묶음이에요. Claude Code는 `/plugin`으로 관리하고, 공식 목록은 anthropics/claude-plugins-official에 있어요.

### 실습 2. 첫 Skill: 변경 요약 (40분)

`.claude/skills/summarize-changes/SKILL.md` (Codex는 `.agents/skills/summarize-changes/SKILL.md`)
```markdown
---
name: summarize-changes
description: 커밋하기 전에 지금까지의 변경 사항을 초보자도 이해할 수 있게 요약할 때 사용한다.

3. 위험해 보이는 변경(삭제, 설정 변경, 비밀 정보)이 있으면 맨 위에 ⚠️로 표시한다.
```

2. 머리말에 `disable-model-invocation: true`를 추가하고, "변경 요약해 줘"라고만 말했을 때 차이를 관찰해요 (Claude Code).

✅ **Done when:** skill이 동작했고, `disable-model-invocation` 전후 차이를 log.md에 적었어요.

### 실습 3. Hooks: 자동 경보기 3개 (60분, Claude Code)

`.claude/settings.json`에 넣어요. (문서 예시를 Python 프로젝트에 맞게 바꾼 거예요. `jq`가 필요해요.)

**① 고친 뒤 자동 포매팅** (문서 예시는 Prettier. Python이면 쓰는 포매터 명령으로 바꾸세요)
```json
{"hooks":{"PostToolUse":[{"matcher":"Edit|Write","hooks":[{"type":"command","command":"npx prettier --write --ignore-unknown \"$(jq -r '.tool_input.file_path')\""}]}]}}
```

**② 특정 폴더 수정 막기** (PreToolUse + 종료 코드 2)
```json
{"hooks":{"PreToolUse":[{"matcher":"Edit|Write","hooks":[{"type":"command","command":"jq -r '.tool_input.file_path' | grep -q '/data/' && { echo 'data/ 폴더는 고칠 수 없어요' >&2; exit 2; } || exit 0"}]}]}}
```

**③ 테스트 통과 전엔 못 끝내기** (Stop hook, 문서의 타입체크 예시를 pytest로)
```json
{"hooks":{"Stop":[{"hooks":[{"type":"command","command":"python3 -m pytest -q 1>&2 || exit 2"}]}]}}
```

> 세 개를 한 파일에 넣을 때는 `"hooks"` 안에 `PostToolUse`, `PreToolUse`, `Stop` 키를 나란히 둬요. `/hooks`로 확인해요.

시험: "data/todos.json을 고쳐 줘" → 막히는지, 일부러 테스트를 깨는 부탁 → Stop hook이 다시 일하게 하는지 봐요.

✅ **Done when:** ②가 수정을 막는 장면과 ③이 테스트 실패 때 에이전트를 다시 일하게 하는 장면을 직접 봤어요.

### 실습 4. 읽기 전용 리뷰어 subagent (40분)

```markdown
name: reviewer
```

✅ **Done when:** 리뷰어가 파일을 **고치지 못하고**(도구가 Read/Grep/Glob뿐) 의견만 냈고, 그 의견 중 1개를 직접 확인했어요.

### 실습 5. MCP 연결하고 끄기 (40분)

1. 쓸 MCP 서버를 하나 골라요 (예: 문서 검색, 브라우저 계열). 서버의 공식 README에 나온 설치 명령을 확인해요.
2. 추가해요.
```bash
# Claude Code (원격 HTTP 서버 예: 문서의 Notion 예시)
claude mcp add --transport http notion https://mcp.notion.com/mcp
# Claude Code (로컬 서버: -- 뒤가 서버 실행 명령)
claude mcp add --transport stdio myserver -- npx server
```
```toml
# Codex: ~/.codex/config.toml
[mcp_servers.myserver]
command = "npx"
args = ["server"]
```
3. `/mcp`로 연결과 도구 목록을 확인하고, 그 도구를 쓰는 작업 1개를 시켜요.
4. 다 쓰면 **꺼요**(Claude는 `/mcp`에서 끄기, Codex는 `codex mcp remove` 또는 config.toml에서 해당 항목 삭제 — `codex mcp --help`로 확인).

✅ **Done when:** MCP 도구를 써서 작업 1개를 끝냈고, 끈 뒤 도구 목록에서 사라진 것을 확인했어요.

## 🧠 스스로 확인 문제

1. CLAUDE.md 규칙을 에이전트가 자꾸 무시해요. 다음에 쓸 도구는?
2. skill의 `description`은 왜 중요한가요?
3. hook에서 종료 코드 2는 무슨 뜻인가요?
4. subagent에게 일을 맡길 때 꼭 해야 할 일은? 그리고 subagent의 비용은?
5. GitHub PR을 다루려는데 MCP와 `gh` CLI 중 무엇을 먼저 고려하나요?

<details><summary>정답 보기</summary>

1. hook(또는 deny 규칙). 쪽지는 "부탁"이라 가끔 놓치고, hook은 프로그램이 강제해요.
2. 에이전트가 description을 보고 "지금 이 skill을 쓸지" 판단하기 때문이에요. 방아쇠 문장이에요.
3. 그 행동을 막고, 에러 출력(stderr)을 에이전트에게 전달해요.
4. subagent는 깨끗한 컨텍스트에서 시작하니까 필요한 정보를 부탁에 다 담아 줘야 해요. subagent도 토큰(비용)을 써요. 병렬 작업이나 새로운 눈이 필요할 때 쓰고, 간단한 일은 가벼운 모델로 해요.
5. `gh` CLI. Claude 문서는 CLI가 있으면 CLI를 먼저 쓰라고 해요. MCP는 도구 이름이 컨텍스트를 차지해요.

</details>
