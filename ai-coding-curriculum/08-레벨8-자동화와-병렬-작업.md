## ❓ 왜 배우나요?

- 개발자는 반복 작업(파일 수십 개 고치기, PR 리뷰, CI 실패 분석)을 **스크립트로 자동화**해요. 에이전트도 스크립트 안에서 돌릴 수 있어요.
- 하지만 **아무도 안 볼 때** 사고가 나면 더 커요. 그래서 이 레벨은 **안전장치**가 절반이에요.
- 여러 에이전트를 동시에 돌리면 빨라지지만, **같은 파일을 동시에 고치면** 엉망이 돼요. 그래서 **격리(worktree)** 를 배워요.

## 📚 핵심 개념

### 1. Headless 모드 (대화 없이 한 번 실행)

- 🧒 **비유:** 도우미에게 **쪽지 한 장 주고 퇴근**하는 거예요. 도우미는 일을 마치고 **결과 쪽지**만 남겨요.
- 📖 **정확히:** 대화창 없이 프롬프트를 한 번 주고, 끝나면 결과를 출력하고 종료해요. 다른 명령과 **파이프(`|`)** 로 이을 수 있어요.

| 도구 | 기본 형태 | 출력 형식 |
|---|---|---|
| Claude Code | `claude -p "질문"` | `--output-format text\|json\|stream-json` (`stream-json`은 `--verbose` 필요) |
| Codex | `codex exec "질문"` (`-`를 주면 stdin에서 프롬프트를 읽어요) | `--json`(JSONL 이벤트), `-o 파일`(마지막 메시지 저장), `--output-schema 파일`(JSON 구조 강제) |
| Cursor CLI [미러] | `agent -p "질문"` | `--output-format text` |

### 2. 안전장치 (Guardrails)

- 🧒 **비유:** 도우미 혼자 두고 갈 때 **"이 방만 써, 1시간만 해, 돈은 만 원까지만"** 이라고 정해 둬요.
- 📖 **정확히:**

| 안전장치 | Claude Code | Codex |
|---|---|---|
| 쓸 수 있는 도구 제한 | `--allowedTools "Read,Edit,Bash(git commit *)"`, `--disallowedTools` | `-s read-only` / `-s workspace-write` |
| 허락 안 된 건 거절 | `--permission-mode dontAsk` | `-a never` (묻지 않고 실패를 모델에게 돌려줌) |
| 반복 횟수 제한 | `--max-turns N` | (`/goal`의 멈춤 조건) |
| 비용 제한 | `--max-budget-usd` | |
| 설정 영향 없이 재현 가능하게 | `--bare` (hooks·skills·플러그인·MCP·CLAUDE.md 건너뜀) | `--ignore-user-config`, `--ephemeral`(세션 기록 안 남김) |

> 💡 `claude -p`는 `default` 권한 모드로 시작해요. `codex exec`는 기본 샌드박스가 `read-only`라서, 파일을 고치게 하려면 `-s workspace-write`를 **명시**해야 해요 (소스 기본값 기준 추론).

**혼자 일 시키기 전 5가지 질문** (Claude `headless.md`)
1. **완료**는 어떤 모습인가요?
2. 스스로 **확인**할 수 있나요?
3. 무엇을 **건드려도** 되나요?
4. 무엇이 **멈추게** 하나요?
5. 누가 **최종 승인**하나요?

### 3. 팬아웃 (Fan-out): 여러 개에 같은 일 나눠 주기

- 🧒 **비유:** 숙제 30장을 **한 장씩** 도우미에게 나눠 줘요. 단, 처음엔 **3장만** 해 보고 설명을 고친 뒤 나머지를 줘요.
- 📖 **정확히:** 반복문으로 파일마다 headless 에이전트를 실행해요. Claude 문서 조언: "**먼저 3개 파일로 시험하고, 프롬프트를 고친 다음, 나머지를 실행하라.**" Claude Code의 `/batch <지시>`는 일을 5~30개 단위로 나눠 각자 worktree에서 처리하고 단위마다 PR을 열어요.

### 4. git worktree (평행 작업실)

- 🧒 **비유:** 같은 레고 세트를 **방 여러 개에 한 벌씩** 펼쳐 놓는 거예요. 도우미마다 자기 방에서 조립하니까 서로 부딪히지 않아요.
- 📖 **정확히:** `git worktree`는 한 저장소에서 **여러 브랜치를 서로 다른 폴더에 동시에** 꺼내 놓는 기능이에요. MIT Missing Semester도 병렬 에이전트에 worktree를 추천해요.

| 도구 | worktree 쓰는 법 |
|---|---|
| git 기본 | `git worktree add ../todo-feature-a -b feature-a`, `git worktree list`, `git worktree remove 경로` |
| Claude Code | `claude --worktree feature-auth` (또는 `-w`) → `<repo>/.claude/worktrees/<이름>`에 생성. 커밋이 최소 1개 있어야 해요. `.worktreeinclude`로 `.env` 같은 gitignore 파일 복사 |
| Codex | `--worktree` 플래그, `/worktree` 명령 |
| Cursor [미러] | Agents Window, `.cursor/worktrees.json`의 `setup-worktree` 명령 배열 |

### 5. Writer/Reviewer 패턴 (쓰는 사람 ≠ 검사하는 사람)

- 🧒 **비유:** 내 글의 맞춤법은 내 눈에 잘 안 보여요. **다른 친구가** 읽어야 보여요.
- 📖 **정확히:** 세션 A가 코드를 쓰고, **대화를 보지 않은** 세션 B가 새 눈으로 리뷰해요.

| 도구 | 리뷰 방법 |
|---|---|
| Claude Code | 새 세션, `/code-review`(새 subagent가 대화 안 보고 diff 리뷰), 레벨 7의 `reviewer` subagent |
| Codex | `/review`, 비대화형 `codex exec review --uncommitted` / `--base <브랜치>` / `--commit <sha>`, `codex review` |
| Cursor [미러] | `/agent-review` — **Quick**(빠르고 저렴) / **Deep**(느리고 비쌈, 보안·복잡한 로직용) |

**좋은 리뷰 기준** (Codex 리뷰 루브릭 `rubric.md`)
- **이번 변경 때문에 새로 생긴**, 구체적이고, **고칠 수 있는** 버그만 지적
- 문제가 생기는 **상황(시나리오)** 을 적기
- 짧게, **아부하지 않기**

### 6. GitHub Actions (클라우드에서 자동으로)

- 🧒 **비유:** 학교 **자동 출석 체크기**예요. 누가 PR을 열거나 댓글을 달면 자동으로 도우미가 출동해요.
- 📖 **정확히:** GitHub Actions는 저장소에서 일이 생길 때 자동으로 작업을 실행하는 기능이에요.
  - **Claude:** `claude` 안에서 `/install-github-app` → GitHub App 설치, 비밀 키(secret) 저장, 워크플로 PR을 열어 줘요 (저장소 관리자 권한 필요). 이슈나 PR 댓글에 **`@claude`** 라고 부르면 일해요. 액션은 `anthropics/claude-code-action@v1`.
  - **Codex:** `openai/codex-action@v1`로 PR 리뷰 봇을 만들 수 있어요.
  - **보안:** 키는 반드시 **GitHub Secrets**에. 권한은 **최소한**으로. claude-code 저장소 자체는 외부 접속 차단(egress firewall) 러너와 허용 목록을 써요.
  - ⚠️ OpenAI 쿡북의 "Autofix GitHub Actions" 노트북은 **보관(ARCHIVED)** 상태예요(보안 우려). 예제로 쓰지 마세요.

### 7. 오래 걸리는 일: `/goal`과 ExecPlan (여행 일지)

- 🧒 **비유:** 긴 여행을 갈 때는 **목적지**(goal)를 정하고, **여행 일지**(PLANS.md)에 "어디까지 왔는지, 무슨 일이 있었는지, 왜 길을 바꿨는지"를 계속 적어요. 그래야 중간에 잠들었다 깨도(새 세션) 이어 갈 수 있어요.
- 📖 **정확히:**

| 도구 | 방법 |
|---|---|
| Claude Code | `/goal all tests in tests/auth pass and lint is clean` — 조건이 맞을 때까지 계속 일해요 |
| Codex (0.128.0+) | `/goal <결과>`, `/goal pause` · `/goal resume` · `/goal clear` |
| Codex ExecPlan | `PLANS.md`를 **살아 있는 문서**로: `Progress`(체크리스트+시간), `Surprises & Discoveries`, `Decision Log`, `Outcomes & Retrospective`. AGENTS.md에 "복잡한 기능은 PLANS.md 규칙에 따라 ExecPlan을 써라"라고 적어요 |
| 긴 작업 파일 묶음 [미러] | `Prompt.md`(목표·제약) / `Plan.md`(마일스톤+검증) / `Implement.md`(실행 규칙) / `Documentation.md`(진행 기록). 공개 예시: derrickchoi-openai/design-desk |

**좋은 goal에 들어갈 것** (Codex 쿡북 `using_goals_in_codex`): 결과물 · 확인 방법 · 제약 · 건드리지 말 것 · 반복 방식 · **막혔을 때 멈추는 조건**

## 🛠️ 실습

> 연습 저장소 `todo-app`에서 해요. 시작 전 `git status`가 깨끗해야 해요.

### 실습 1. 파이프로 한 번 실행 (20분)

```bash
cd ~/ai-practice/todo-app
git log --oneline -20 | claude -p "summarize these recent commits"
# 또는
codex exec "이 저장소의 테스트를 실행하는 명령을 찾아서 알려 줘. 파일은 고치지 마."
# 또는
agent -p "이 저장소를 세 줄로 설명해 줘" --output-format text
```

✅ **Done when:** 대화창 없이 결과만 출력되고 프로그램이 끝났어요. `git status`는 깨끗해요.

### 실습 2. 기계가 읽는 출력 (30분)

```bash
claude -p "tests 폴더의 테스트 파일 목록을 알려 줘" --output-format json | jq .
```
→ `jq .`로 JSON 구조를 먼저 살펴보고, 원하는 필드만 꺼내는 `jq` 명령을 스스로 써 봐요.

Codex는 결과 모양을 **강제**할 수 있어요.
```bash
cat > schema.json << 'EOF'
{
  "type": "object",
  "properties": {
    "test_command": {"type": "string"},
    "test_files": {"type": "array", "items": {"type": "string"}}
  },
  "required": ["test_command", "test_files"],
  "additionalProperties": false
}
EOF
codex exec --output-schema schema.json -o result.json "이 저장소의 테스트 실행 명령과 테스트 파일 목록을 알려 줘"
cat result.json
```

✅ **Done when:** JSON 결과에서 `jq`로 값 하나를 꺼냈어요(또는 `result.json`이 스키마 모양이에요). 실습 후 `schema.json`, `result.json`은 지워요.

### 실습 3. 팬아웃: 3개 먼저 (45분)

1. `ls *.py tests/*.py > files.txt`로 대상 목록을 만들고, **위 3줄만** 남겨요.
2. Claude 문서의 패턴을 따라 실행해요.
```bash
for file in $(cat files.txt); do
  claude --bare -p "Add a short Korean docstring to every function in $file that has none and commit. Reply OK or FAIL." \
    --allowedTools "Read,Edit,Bash(git add *),Bash(git commit *)" \
    --permission-mode dontAsk --max-turns 20
done
```
3. `git log --oneline`과 `git show`로 결과를 **한 커밋씩** 검토해요. 마음에 안 들면 프롬프트를 고치고 `git revert`.
4. (선택) Codex로 같은 일: `codex exec -s workspace-write "..."`

✅ **Done when:** 3개 파일 결과를 검토하고, 프롬프트를 1번 이상 고친 기록을 log.md에 남겼어요.

### 실습 4. worktree로 두 도우미 동시에 (45분)

터미널 두 개를 열어요.
```bash
# 터미널 1
cd ~/ai-practice/todo-app
claude -w feature-search        # "할 일 검색 기능을 추가하고 테스트해 줘"
# 터미널 2
cd ~/ai-practice/todo-app
claude -w docs-readme           # "README에 설치와 사용법을 정리해 줘"
```
(git만 쓰려면: `git worktree add ../todo-search -b feature-search` 후 그 폴더에서 Codex나 Cursor 실행)

끝나면 두 브랜치를 각각 검토하고 main에 merge해요. `git worktree list`로 확인하고 다 쓴 worktree는 `git worktree remove`로 정리해요.

✅ **Done when:** 두 브랜치가 충돌 없이 main에 merge됐고, 남은 worktree가 없어요.

### 실습 5. Writer/Reviewer (45분)

1. **세션 A (Writer):** "할 일에 우선순위(높음/보통/낮음) 기능을 추가하고 테스트해 줘." → 커밋하지 말고 둬요.
2. **세션 B (Reviewer, 새로 시작):**
```text
지금 커밋되지 않은 변경을 리뷰해 줘. 이번 변경 때문에 새로 생긴, 실제로 고칠 수 있는 버그만 지적해.
각 지적마다 파일:줄, 문제가 생기는 상황, 고치는 방향을 짧게 써 줘. 스타일 지적은 빼.
```
   또는 `codex exec review --uncommitted`, Claude `/code-review`, Cursor `/agent-review`.
3. **나(사람)도** 같은 기준으로 diff를 리뷰해요.
4. 세 리뷰(에이전트 B, 나, 선택: 다른 도구)를 비교해요.

✅ **Done when:** 에이전트 리뷰와 내 리뷰의 비교표(찾은 문제 / 놓친 문제 / 틀린 지적)를 만들었어요.

### 실습 6. GitHub Actions 리뷰 봇 (60분)

**연습용 공개 저장소**에서만 해요.

**Claude 방식**
1. `claude` 안에서 `/install-github-app` → 안내를 따라 App 설치, secret 저장, 워크플로 PR merge
2. 이슈를 열고 댓글: `@claude README에 "테스트 실행 방법" 섹션을 추가해 줘`
3. 에이전트가 만든 PR을 **내가 리뷰**하고 merge 또는 닫기

**Codex 방식** (`.github/workflows/`에 워크플로 추가, 전체 예시는 openai/codex-action README 확인)
```yaml
- uses: openai/codex-action@v1
  with:
    openai-api-key: ${{ secrets.OPENAI_API_KEY }}
    prompt: "Review this PR ..."
```

**보안 체크리스트**
- [ ] API 키는 Secrets에만 있고 코드·로그에 없다
- [ ] 워크플로 권한은 필요한 만큼만 줬다
- [ ] 에이전트의 PR은 사람이 승인해야 merge된다 (브랜치 보호)
- [ ] 비용 한도(`--max-turns` 등 `claude_args`)를 정했다

✅ **Done when:** 에이전트가 연 PR 또는 리뷰 댓글이 1개 이상 있고, 보안 체크리스트를 다 채웠어요.

### 실습 7. 여행 일지와 함께 긴 목표 (60~90분)

1. 새 브랜치 `export`에서 시작해요: `git switch -c export`
2. 에이전트에게 먼저 **계획 문서만** 쓰게 해요.
```text
할 일 목록을 CSV 파일로 내보내는 기능(todo.py export)을 만들 거야. 아직 코드는 쓰지 마.
PLANS.md에 ExecPlan을 써 줘. 섹션: 목표, 단계별 계획, 검증 방법(테스트 명령),
Progress(체크리스트), Surprises & Discoveries, Decision Log, Outcomes & Retrospective.
처음 보는 사람도 이 문서만 읽고 구현할 수 있게 써 줘.
```
3. 내가 PLANS.md를 읽고 고친 뒤 커밋해요.
4. 긴 목표를 줘요.
```text
/goal PLANS.md의 계획을 끝까지 구현하고 python3 -m pytest -q가 모두 통과한다.
단계를 끝낼 때마다 PLANS.md의 Progress를 갱신하고 커밋해.
같은 에러로 세 번 실패하면 멈추고 무엇이 막혔는지 PLANS.md에 적어.
```
5. 중간에 세션을 끊고 **새 세션**에서 "PLANS.md를 읽고 이어서 해 줘"로 이어 가 봐요.

✅ **Done when:** PLANS.md의 Progress가 작업 중에 여러 번 갱신된 기록이 `git log`에 있고, 새 세션이 문서만 보고 이어서 일했어요.

## 🏁 마일스톤 체크리스트: ⚙️ 혼자 일하는 에이전트

다 체크하면 [레벨 9](09-레벨9-개발자-수준-졸업.md)로 가요.

- [ ] `claude -p` 또는 `codex exec`를 파이프와 함께 써서 결과를 받았다
- [ ] JSON 출력을 `jq`나 `--output-schema`로 처리했다
- [ ] 도구 제한 + 횟수(또는 비용) 제한을 건 팬아웃 스크립트를 3개 파일에 돌리고 결과를 검토했다
- [ ] worktree 2개로 동시에 작업해 두 브랜치를 merge했다
- [ ] Writer/Reviewer 비교표를 만들었다
- [ ] GitHub Actions로 에이전트가 PR 또는 리뷰 댓글을 남겼고, 보안 체크리스트를 채웠다
- [ ] PLANS.md + `/goal`로 긴 작업을 하고, 새 세션이 문서만 보고 이어 간 기록이 있다
- [ ] **AI 없이** "혼자 일 시키기 전 5가지 질문"을 말할 수 있다
- [ ] 🧠 문제를 답을 보지 않고 4개 이상 맞혔다

## ⚠️ 흔한 실수

| 실수 | 이렇게 해요 |
|---|---|
| 자동화에 `bypassPermissions`/`--yolo` 사용 | `dontAsk` + `--allowedTools`, `-s workspace-write`처럼 **좁게** |
| 횟수·비용 제한 없이 돌림 | `--max-turns`, `--max-budget-usd` |
| 결과를 검토하지 않고 merge | 커밋 하나씩 `git show`로 검토, 사람이 승인 |
| API 키를 워크플로 파일에 직접 씀 | GitHub Secrets 사용 |
| worktree를 만들고 안 지움 | `git worktree list` → `remove` |
| 리뷰 봇 의견을 전부 믿음 | 봇 리뷰는 **보조**예요. 최종 판단은 사람 |
| 보관된(ARCHIVED) 예제를 따라 함 | 날짜와 상태를 확인. 예: Codex 쿡북 Autofix 노트북, `codex mcp-server`(deprecated) |
