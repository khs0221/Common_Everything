# 회의 녹음·기록 프로그램

Teams 같은 화상회의를 내 PC 에서 녹음하고, PC 안에서 글로 옮겨 **발언자별 기록**을 만듭니다.
요약은 이 프로그램이 하지 않습니다. 만들어진 `Copilot용.txt` 를 회사 Microsoft Copilot 에 붙여 넣어 요약합니다.

- 회의 내용을 바깥으로 보내지 않습니다. 글로 옮기는 모델까지 모두 프로그램 폴더 안에 들어 있고,
  프로그램의 파이썬 코드가 바깥으로 연결하려 하면 막도록 해 두었습니다.
  단, 이 차단은 프로그램 안에서 거는 것이라 윈도우 방화벽처럼 모든 경로를 막는 장치는 아닙니다
  (함께 쓰는 C++ 부품 내부의 연결까지 막지는 않습니다. 이 부품들이 접속하는 코드는 찾지 못했습니다).
  확실히 하려면 회사 보안 프로그램·방화벽 규칙으로 이 exe 의 인터넷 연결을 막아도 프로그램은 그대로 동작합니다.
- 파이썬 등을 설치할 필요가 없습니다. 압축을 풀고 실행하면 됩니다.
- 회의 언어: 영어, 한국어(자동 판별 가능).

> 녹음하기 전에 참석자에게 녹음한다고 알리고 동의를 받으십시오. 회사 규정도 확인하십시오.

## 1. 내려받기

준비물: 이 저장소를 볼 수 있는 **깃허브 계정**(로그인해야 내려받을 수 있습니다).

1. 웹 브라우저로 깃허브에 **로그인**한 뒤 이 저장소 페이지를 엽니다.
2. 위쪽 **Actions** 탭 → 왼쪽 목록의 **회의 녹음 프로그램 윈도우 빌드** 를 누릅니다.
3. 오른쪽 목록에서 **초록색 체크** 표시이면서 이름 옆에 **main** 이라고 적힌 실행(또는 **Manually run** 이라고 적힌 실행)을 누릅니다.
   - exe 묶음은 이 두 가지 실행에만 올라갑니다. 다른 브랜치 이름이 적힌 실행은 시험만 하므로 **Artifacts** 에 묶음이 없습니다.
4. 아래로 내려 **Artifacts** 칸의 **MeetingRecorder-windows** 를 누르면 zip 파일(약 1.3GB)이 내려받아집니다.
   - **묶음은 만들어진 뒤 7일이 지나면 사라집니다.** 또 매주 정리 작업이 돌아 **최신 2개만** 남깁니다.
   - 목록에 묶음이 없으면, 저장소 권한이 있는 경우 오른쪽 위 **Run workflow** → **Branch: main** → 초록색 **Run workflow** 를 누르고
     20~30분 뒤 새로 생긴 실행에서 받으십시오. 권한이 없으면 담당자에게 만들어 달라고 요청하십시오.
   - `selftest-result` 는 개발용 시험 결과이니 받지 않아도 됩니다.

## 2. 압축 풀기

1. **파일 탐색기**를 열고 왼쪽에서 **다운로드** 폴더를 누릅니다.
2. 내려받은 zip 파일을 **오른쪽 클릭 → 속성** → 아래쪽에 **차단 해제** 칸이 있으면 체크 → **확인**.
   (실행할 때 경고가 덜 뜹니다. 칸이 없으면 그냥 확인.)
3. 풀 곳 만들기: 파일 탐색기 위쪽 주소 칸을 누르고 `%USERPROFILE%` 를 입력한 뒤 **Enter** →
   내 사용자 폴더가 열립니다 → 빈 곳 **오른쪽 클릭 → 새로 만들기 → 폴더** → 이름을 `MeetingRecorder` 로 적습니다.
   - 사용자 폴더는 회사 PC 에서도 보통 쓰기가 허용되고, OneDrive 동기화 대상이 아니어서 1GB 넘는 파일이 올라가지 않습니다.
   - 바탕 화면이나 문서 폴더가 OneDrive 와 동기화되는 PC 라면 그곳에는 풀지 마십시오(용량이 큼).
4. zip 파일을 **오른쪽 클릭 → 모두 압축 풀기** → **찾아보기** → 방금 만든 `MeetingRecorder` 폴더 선택 → **압축 풀기**.
5. 처음 실행했을 때 "경로에 한글이 있어 모델을 못 읽을 수 있습니다" 경고가 뜨면(윈도우 사용자 이름이 한글인 경우 등),
   `C:\MeetingRecorder` 처럼 영어로만 된 곳에 다시 풀어 보십시오. C 드라이브 바로 아래에 폴더를 만들 수 없게 막힌 PC 라면 담당자에게 문의하십시오.

## 3. 실행 전 확인: 윈도우 마이크 권한

윈도우가 마이크를 막고 있으면 녹음은 되지만 **내 목소리가 무음으로** 저장됩니다.

1. **시작** → **설정**(톱니바퀴) → **개인 정보 및 보안**(윈도우 10 은 **개인 정보**) → **마이크**.
2. **마이크 액세스** 가 **켬** 인지 확인합니다.
3. 아래쪽 **데스크톱 앱이 마이크에 액세스하도록 허용** 이 **켬** 인지 확인합니다.
   (회사 정책으로 바꿀 수 없게 잠겨 있으면 IT 담당자에게 문의하십시오.)

## 4. 실행

1. `MeetingRecorder` 폴더의 **MeetingRecorder.exe** 를 두 번 누릅니다.
2. "Windows의 PC 보호" 파란 창이 뜨면 **추가 정보 → 실행** 을 누릅니다.
   (회사 보안 정책으로 실행 자체가 막히면 IT 담당자에게 문의해야 합니다.)
3. 바탕 화면에 바로 가기를 만들려면 exe 를 **오른쪽 클릭 → 바로 가기 만들기** 후 바탕 화면으로 옮깁니다.

## 5. 첫 시험(1분)

1. 헤드셋(또는 이어폰)을 꽂습니다. **헤드셋을 권장하는 이유**: 스피커로 들으면 상대방 목소리가 내 마이크에도
   들어가서, 같은 말이 '나' 와 '참석자' 로 두 번 기록됩니다.
2. 창 **1. 장치** 는 처음에 두 칸 모두 **자동(윈도우에서 쓰는 장치 그대로)** 입니다. **보통은 그대로 두십시오.**
   - 자동이면 윈도우가 지금 쓰는 마이크·스피커를 그대로 녹음하고, 녹음 중에 헤드셋을 꽂아 윈도우 장치가 바뀌어도 따라갑니다.
   - 장치 목록이 비어 있어도 자동으로는 녹음할 수 있습니다.
   - 특정 장치로 고정하고 싶을 때만 칸을 눌러 장치를 고릅니다. **(현재 기본)** 이 붙은 장치를 골라도 그 장치로 고정됩니다.
   - Teams 소리가 다른 장치로 나오도록 Teams 에서 따로 정해 두었다면(**설정 → 장치 → 스피커**), **상대방 소리(스피커)** 를 그 장치로 고정하십시오.
   - 칸 아래에 빨간 글씨로 문제가 표시되면 **장치 새로고침** 을 눌러 보십시오. 계속되면 **오류 내용 복사** 를 누른 뒤
     메일·메신저에 붙여 넣어 담당자에게 보내 주십시오(프로그램 버전·윈도우 버전·오류 내용만 들어 있고 회의 내용은 없습니다).
3. 유튜브 영상 하나를 틀어 둡니다(상대방 소리 대신).
   - 녹음 전에 **장치 점검** 을 누르면 고른 마이크·스피커를 1초씩 열어 보고 "열림"·소리 크기를 알려 줍니다.
     "열지 못함" 이 나오면 '자동'으로 바꾸거나 다른 장치를 골라 다시 점검하고, 계속되면 **오류 내용 복사** 를 눌러
     담당자에게 보내 주십시오(장치를 열려고 시도한 방법별 결과가 들어 있습니다. 회의 내용은 없습니다).
4. **● 녹음 시작** 을 누르고, 30초쯤 직접 말해 봅니다.
   - **나(마이크)** 막대가 내 목소리에 맞춰 움직이는지,
   - **상대방(스피커)** 막대가 영상 소리에 맞춰 움직이는지 확인합니다.
   - 막대가 안 움직이면 **■ 중지** 후 윈도우의 소리 설정(작업 표시줄 스피커 아이콘)에서 쓰는 장치를 확인하거나, 장치를 직접 골라 고정해 봅니다.
5. **■ 중지** 를 누르면 자동으로 **글로 옮기기**가 시작됩니다. 진행 막대와 남은 시간이 보입니다.
6. 끝나면 "참석자 이름을 정할까요?" 가 뜹니다. **예** → 참석자마다 대표 발언을 보고 이름을 적고 **저장**.
7. **결과 폴더 열기** 를 눌러 결과를 확인합니다.

## 6. 실제 회의에서

1. 회의 시작 직전에 **● 녹음 시작**, 회의가 끝나면 **■ 중지**.
2. 글로 옮기는 모델은 large-v3-turbo 하나입니다(R6 에서 '빠름' 선택을 없애 내려받는 크기를 줄였습니다).
   처리 시간 안내는 창의 **3. 글로 옮기기** 아래에 나옵니다(측정값 기준, PC 에 따라 다름).
   처리 중에도 다른 일을 할 수 있지만 PC 가 느려질 수 있습니다(계산에는 코어 하나를 남기고 씁니다).
3. 처리 중 **처리 취소** 를 눌러도 녹음 파일은 남습니다. 나중에 **회의 폴더 다시 처리…** 로 다시 할 수 있습니다.
4. 언어는 보통 **자동(영어/한국어)** 으로 둡니다. 자동이면 발언마다 영어인지 한국어인지 따로 판별하므로, 한국어로 말하다 영어로 바꿔도
   영어는 영어로, 한국어는 한글로 적힙니다(번역하지 않음). 회의 전체가 한 언어인데 판별이 틀리면 **영어** 또는 **한국어** 로 정하고 다시 처리합니다.
5. 상대방 인원을 알면 **상대방 인원(나 제외)** 에서 고르면 발언자 구분이 더 정확해질 수 있습니다.

## 7. 결과물(회의마다 폴더 1개)

저장 폴더(기본: `문서\회의기록`) 아래에 `회의_날짜_시각` 폴더가 생깁니다.

| 파일 | 내용 | 쓰는 곳 |
|---|---|---|
| `마이크_나.wav` | 내 목소리 녹음 | |
| `스피커_상대방.wav` | 상대방(스피커로 나온 소리) 녹음 | |
| `기록.md` | 시각·발언자·내용을 시간순으로 정리한 **원문** 기록(고치지 않은 그대로) | 보관·확인용 |
| `대화록.txt` | 지시문 없이 대화록만(맨 위에 길이·언어·발언자 머리말). 줄마다 `[시:분:초] 발언자: 내용` | 파일을 받아 처리하는 AI 도구에 `교정지침.md` 와 함께 올려 교정 |
| `교정지침.md` | 교정 규칙 + 분야 용어 목록(`glossary/glossary_full.txt` 로 처리 때마다 다시 만듦) | 위 AI 도구에 대화록과 함께 줌 |
| `Copilot용.txt` | 교정 규칙·요약 요청 + 용어 목록 + 대화록을 한 파일로 합친 것 | 채팅창에 붙여 넣기 |
| `처리결과.json` | 이름 바꾸기에 쓰는 원자료 | |
| `녹음정보.json` | 녹음 길이 등 기술 정보 | |

- 참석자 이름을 정하면 `기록.md`·`대화록.txt`·`Copilot용.txt`·`교정지침.md` 가 모두 다시 써집니다.
- `교정지침.md` 와 `Copilot용.txt` 의 교정 규칙은 같은 문장입니다(프로그램 한 곳에서 만듦).

**채팅으로 요약하기**: `Copilot용.txt` 를 메모장으로 열기 → **Ctrl+A**(모두 선택) → **Ctrl+C**(복사) →
Copilot 입력창에 **Ctrl+V** → 보내기. 너무 길다고 하면 파일을 첨부해 보십시오.

**파일로 교정하기**: `대화록.txt` 와 `교정지침.md` 를 파일을 받아 처리하는 AI 도구에 올리고
"교정지침대로 대화록을 교정하고, 교정본과 변경 목록을 파일로 주세요" 라고 요청합니다.

## 8. 분야 용어 파일(프로그램 폴더의 `glossary`)

| 파일 | 용도 |
|---|---|
| `hint_terms.txt` | 글로 옮길 때 영어 묶음에 주는 **인식 힌트**(중요한 것부터, 앞쪽 일부만 쓰임: 화면에 개수 표시) |
| `glossary_full.txt` | `교정지침.md`·`Copilot용.txt` 에 들어가는 **전체 용어 목록** |
| `교정지침.md` | 프로그램이 만드는 파일(직접 고치지 마십시오) |

- 메모장으로 열어 고칠 수 있습니다. **한 줄에 용어 하나**가 기본입니다. 예:

  ```
  # 공정능력
  Cpk
  Gage R&R
  UN 38.3
  X-bar R chart
  ```

  `#` 으로 시작하는 줄은 설명(무시됨), 빈 줄은 괜찮습니다. 다른 도구로 만든 파일도 읽도록 너그럽게 처리합니다:
  줄 앞의 `-`·`*`·`•`·`1.` 같은 글머리표와 따옴표는 지우고, 한 줄에 쉼표·세미콜론으로 여럿 적혀 있으면 나누며
  (`1,000` 처럼 숫자 사이 쉼표는 그대로), `용어 - 설명`·`용어: 설명` 은 앞의 용어만 씁니다. 60자가 넘는 줄은 용어가 아닌
  것으로 보고 건너뛰고 화면에 개수를 알립니다. 같은 용어는 대소문자와 상관없이 한 번만 씁니다. UTF-8·ANSI(CP949) 저장 모두 읽습니다.
- 창의 **3. 글로 옮기기** 아래에 "힌트 파일 N개 읽음 중 M개 사용" 처럼 읽은 수와 실제 힌트에 쓰인 수가 보입니다.
- 창 **3. 글로 옮기기** 의 **용어 파일 열기** 로 폴더를 열 수 있습니다. 고친 내용은 다음 처리부터 쓰입니다.
- **새 판으로 바꿀 때**: 새 판 압축을 푼 뒤, 예전 판 `glossary` 폴더의 `hint_terms.txt`·`glossary_full.txt`
  두 파일을 새 판 `glossary` 폴더에 덮어쓰기로 복사하십시오(고친 적이 없으면 할 필요 없음).

## 9. 알아 둘 점

- 녹음 중 프로그램이 갑자기 꺼져도 그때까지의 녹음은 wav 파일로 남습니다. **회의 폴더 다시 처리…** 로 처리하면 됩니다.
- 녹음 중 장치가 빠지거나 끊기면 창에 **빨간 경고**가 뜨고, 1초마다 다시 연결을 시도합니다. 끊긴 동안은 무음으로 채워져
  두 트랙의 시각은 맞게 유지됩니다. 경고가 계속되면 장치를 다시 꽂거나 **■ 중지** 후 장치를 다시 고르십시오.
- 녹음 파일 크기: 트랙마다 1시간에 약 115MB(두 트랙 합계 약 230MB).
- 원격(가상) PC 에서 쓸 때: 회의 프로그램이 소리를 가상 PC 를 거치지 않고 지금 쓰는 단말에서 바로 내보내는 설정이면,
  이 프로그램은 상대방 소리를 녹음하지 못합니다(상대방 막대가 계속 움직이지 않고, 1분 뒤 안내가 뜹니다).
- 아주 작게 녹음된 트랙은 말소리를 찾을 때만 자동으로 키워서 봅니다(녹음 파일과 글로 옮기는 소리는 그대로).
- 자동 변환이라 단어와 발언자 구분이 틀릴 수 있습니다. 중요한 내용은 녹음을 들어 확인하십시오.
- 녹음·기록 파일에는 회의 내용이 들어 있습니다. 회사 규정에 맞게 보관하고 지우십시오.
- 프로그램 기술 기록(오류 등, 회의 내용 없음)은 `%LOCALAPPDATA%\MeetingRecorder\logs` 에 남습니다.

## 10. 알려진 한계

시험 표본으로 확인한 한계입니다. 중요한 내용은 녹음을 들어 확인하십시오.

- **아주 짧은 발언(1초 안팎)**: 영어 사이에 끼어 1초 남짓 말한 한국어(또는 그 반대)는 결과에서 빠질 수 있습니다.
  1초 길이에서는 말소리로 잡히지 않거나, 언어를 정하지 못하는 경우가 있기 때문입니다. 1.5초 정도면 시험 표본에서는 모두 적혔습니다.
  언어를 잘못 정해 한국어가 영어 글자로, 영어가 한글로 적히는 일은 시험에서 없었지만, 없다고 보장하지는 못합니다.
- **한 문장 안에서 한국어와 영어를 섞어 말할 때**: 문장 하나는 한 언어로 적습니다. 한국어 문장 속 영어 단어는 한글로
  소리 나는 대로 적히거나, 영어 문장 속 한국어 단어가 빠질 수 있습니다.
- **말이 없는 잡음 구간**: 음악·웅웅거림 같은 잡음이 길게 이어지면 말하지 않은 짧은 글("Thank you.", "감사합니다." 등)이
  적힐 수 있습니다. 대부분은 말소리를 찾는 단계에서 걸러지고, 소리가 거의 없는 구간에서 생긴 글은 따로 빼며 처리가 끝날 때
  "말소리 없는 구간의 글 N건 제외" 로 알려 드립니다. 실제 말을 버리지 않도록 소리 크기나 확신 정도로는 거르지 않습니다.
  - 이 거르기를 끄려면 프로그램을 닫고 `%APPDATA%\MeetingRecorder\settings.json` 을 메모장으로 열어
    맨 위 `{` 바로 다음 줄에 `"tail_text_guard": false,` 한 줄을 넣고 저장하십시오(다시 켜려면 그 줄을 지우십시오).
- **용어 힌트**: `hint_terms.txt` 는 앞쪽 일부(약 33개, 창에 개수 표시)만 인식 힌트로 쓰입니다. 중요한 용어를 위쪽에
  두십시오. 나머지 용어는 `교정지침.md`·`Copilot용.txt` 의 교정 목록에만 들어갑니다.
- **발언자 구분**: 상대방 목소리가 비슷하거나 동시에 말하면, 한 사람을 둘로 나누거나 두 사람을 하나로 묶을 수 있습니다.
  **참석자 이름** 에서 바로잡을 수 있습니다.
- **실제 PC 에서 확인하지 못한 것**: 시험은 자동 시험 환경(윈도우 빌드 서버, 리눅스)에서 했습니다. 다음은 실제 PC 에서 아직 확인하지 못했습니다.
  - 여러 종류의 마이크·스피커 장치가 열리는지
  - 장치가 빠졌다 다시 꽂힐 때 다시 연결되는지
  - 처리 시간(창에 보이는 예상 시간은 시험 환경 기준)
