# R2 결과 — 실기기에서 장치를 못 읽는 문제

작성: 총괄, 2026-11-24

## 결론
원인을 윈도우 CI 에서 재현해 확정하고 고쳤습니다. 감사 치명 0 / 중요 0 / 보통 0 / 경미 4. 사용자 PC 에서 실제로 목록이 채워지고 녹음되는지는 재시험이 필요합니다.

## 원인
`_run_in_mta` 가 COM 을 먼저 초기화한 스레드에서 soundcard 를 불러와, soundcard 의 CoInitializeEx 가 S_FALSE 를 받고 예외(`RuntimeError: Error 0x100000001`)를 냈습니다. R1 수정 1회차(F1)에서 생긴 순서이고, 당시 자체 시험은 주 스레드에서 직접 불러와 이 경로를 지나지 않았습니다.

## 바꾼 것
- soundcard 를 COM 을 먼저 초기화하지 않은 새 스레드에서 불러옴. 녹음 스레드 COM 규칙(F1) 유지.
- 장치 선택 기본값 '자동(윈도우에서 쓰는 장치 그대로)'. 목록을 못 읽어도 자동으로 녹음 시작. 특정 장치 고르면 고정(N3 해결).
- 장치 계층 실패 시 원인 문구와 [오류 내용 복사]. [장치 새로고침]은 처음부터 재시도.
- N1 수정(녹음 시작 실패 시 스레드 정지·장치 닫기).
- 자체 시험에 화면과 같은 장치 경로 검사 추가(수정 전 실패 → 수정 뒤 통과).

## 검증
- 윈도우 CI: 수정 전 실행 45306743702 실패(재현), 수정 뒤 실행 45308321266 성공.
- pytest: 화면 있음 68 통과 / 화면 없음 63 통과 + 5 실행 안 함.

## 교훈
- 감사 지적을 고친 변경(F1)이 실기기 경로를 깼고, CI 자체 시험이 제품과 다른 경로를 타서 놓쳤습니다. 자체 시험은 제품이 실제로 쓰는 경로를 그대로 지나야 합니다.
- CI 러너에는 소리 장치가 없어 스트림 열기·실제 녹음은 여전히 사용자 PC 에서만 확인됩니다.

## 남은 것
- 사용자 PC 재시험: 목록 표시, 자동 녹음, 두 트랙 기록, 처리 시간, 장치 끊김 경고.
- R3: E1(오류 복사 내용의 사용자 경로 가리기), E3, N2, F12, F7 잔여.
- 사용자 결정 대기: Teams 녹화 파일 처리, Copilot 입력 한도에 맞춘 파일 나누기.
