## 3-1. 언어를 발언 단위로 판별

### 재현(수정 전 R2 코드, 커밋 530fea4)
표본은 공개 음성 Google FLEURS(ko_kr·en_us dev, CC BY 4.0)와 저장소의 합성 표본을 이어 붙여 만들었습니다(만든 도구는 실험용, 저장소 밖).
발언마다 크기를 맞췄습니다. 모두 한 트랙(같은 '나' 트랙)으로 처리했습니다.

| 세트 | 구성 | 수정 전 발언별 언어 정답 | 영어→한글 | 한국어→영문 | 빠짐 |
|---|---|---|---|---|---|
| A | 영·한 번갈아(간격 0.6~1.2초), 영어로 시작 | 5/12 | 3 | 0 | 4 |
| B | 같은 방식, 한국어로 시작 | 5/12 | 0 | 0 | 7 |
| C | **한국어 3문장 → 영어 3문장 → 한국어 2 → 영어 3 → 한국어 1**(간격 0.25~0.4초, 같은 흐름에서 전환. 사용자 보고와 같은 경우) | 6/12 | 3 | 0 | 3 |
| D | 영어 → 한국어 흐름 전환(간격 0.25~0.4초) | 7/10 | 0 | 3 | 0 |
| E | 영어만, 앞 6초 합성 음악(보고 (b) 경우) | 6/6 | 0 | 0 | 0 |
| 합계 | | **29/52** | **6** | 3 | 14 |

- 실제 번역 예(C): "The first cases of the disease this season were reported in late July." → "첫 번째 기준의 상황은 지난주에 제작되었습니다."
- 같은 구간을 '한국어' 로 강제하면 "Three more bombs exploded…" → "3번의 공간이 2시간 정도의 공간을 제거하고 있습니다." 처럼 번역되어 나옵니다.
- **원인 확정**:
  - `transcribe_file` 은 말소리를 최대 180초씩 이어 붙인 묶음마다 `model.transcribe(language=None)` 을 한 번 부릅니다.
  - faster-whisper 1.2.1 은 이때 언어를 묶음의 첫 30초로 한 번 정하고(`transcribe.py` 472~497줄 `detect_language`), 그 언어 토큰을 묶음 끝까지 씁니다.
  - 그래서 한국어로 시작한 묶음 안의 영어는 '한국어로 적으라' 는 지시를 받아 한국어로 번역되거나, 버려졌습니다.
- 영어만 있는 트랙(E, 앞에 음악)은 수정 전에도 틀리지 않았습니다. 다만 앞 30초가 한국어로 오판되면 같은 경로로 전부 번역될 수 있는 구조였습니다.
- 한 트랙의 판별이 다른 트랙에 영향을 주는 경로: **없음**.
  - 트랙마다 따로 판별하고, faster-whisper 는 호출마다 tokenizer·언어를 새로 정합니다.
  - 확인: 한국어 섞인 마이크 트랙 + 영어 스피커 트랙을 함께 처리한 결과와 각각 따로 처리한 결과가 글자까지 같았습니다.

### faster-whisper 옵션 확인(설치된 1.2.1 소스)
- `multilingual=True`:
  - `generate_segments` 1192~1199줄에서 **30초 디코딩 창마다** `detect_language` 를 합니다. 발언 단위가 아닙니다.
  - 후보 언어를 영어·한국어로 제한할 수 없습니다(전 언어 중 1위).
- `language_detection_segments`·`language_detection_threshold`: 첫 판별에 쓸 창 수와 기준일 뿐이고, 판별은 여전히 한 번입니다.
- `WhisperModel.detect_language`: 음성을 30초로 늘려 인코더를 돌립니다(30초 창 1개 0.62초).
- CTranslate2 의 `model.encode` 는 30초보다 짧은 입력도 받습니다. 2.7초 구간에서 0.62초 → 0.03초였고, 언어 확률도 같았습니다(en 0.96 / 0.98).

### 짧은 입력 판별 정확도(FLEURS 각 80문장, 앞뒤 무음 자른 구간)

| 창 길이 | 정답률 | '확실'(영·한 중 큰 확률 ≥0.6) 비율 | 확실한데 틀림 |
|---|---|---|---|
| 1.0초 | 83% | 46% | 1/138 |
| 1.5초 | 89% | 68% | 0/206 |
| 2.0초 | 90% | 80% | 0/241 |
| 3.0초 | 97% | 91% | 0/265 |
| 문장 전체(30초로 안 늘림 / 늘림) | 132/132 / 132/132 | | 0 |

틀린 판정은 모두 확률이 낮았습니다(다른 언어로 흩어짐). 그래서 '확실' 기준(0.6)으로 믿을 것과 이웃으로 채울 것을 나눕니다.

### 방식 비교(위 5개 세트, 평가 조건을 같게 하려고 모든 방식에서 '언어가 다르면 줄을 합치지 않음')

| 방식 | 정답 | 영어→한글 | 한국어→영문 | 빠짐 | 처리 시간 합(초, 음성 263초) |
|---|---|---|---|---|---|
| 수정 전(R2) | 29/52 | 6 | 3 | 14 | 54.9 |
| (b) `multilingual=True` | 29/52 | 3 | 7 | 13 | 47.8 |
| 말소리 구간마다 따로 글로 옮기기(언어 자동) | 50/52 | 1 | 1 | 0 | 95.7 |
| (a) 구간 판별 후 **연속된 같은 언어끼리** 묶기 | 52/52 | 0 | 0 | 0 | 62.0 |
| **(a') 구간 판별 후 언어별로 트랙 전체를 묶기(채택)** | **52/52** | **0** | **0** | **0** | **45.4** |

- 수정 전 B 세트의 28.4초는 whisper 의 반복 재시도(fallback)가 겹친 값입니다. B 를 빼면 수정 전 합 26.5초 → 채택 36.1초입니다.
- 60초 안팎의 짧은 세트에서는 언어마다 whisper 호출이 하나씩 생겨 고정 비용이 보입니다. 긴 녹음에서는 아래처럼 차이가 작습니다.

### 채택: `mrec/langid.py` + `Transcriber.transcribe_file`
1. 말소리 구간(VAD)마다 판별합니다. 4초 이하는 통째로, 긴 구간은 3초 창을 1.5초 간격으로 봅니다.
   whisper 인코더를 30초로 늘리지 않고 돌려 영·한 확률을 얻습니다(`WhisperLangProbe`).
2. 한 구간 안에서 확실한 창의 언어가 바뀌면, 그 사이에서 가장 조용한 20ms 지점에서 구간을 나눕니다. 쉬지 않고 언어를 바꿔 말한 경우입니다.
3. 확실하지 않은 조각(짧은 "네", "Okay" 등)만 시간상 가장 가까운 확실한 조각의 언어를 따릅니다. **확실한 판정은 바꾸지 않으므로** 같은 사람의 언어 전환을 덮어쓰지 않습니다.
   트랙 전체가 불확실하면 확률 합으로 정합니다.
4. 언어별로 조각을 모아(떨어진 조각도) 180초 묶음으로 이어 붙이고, 그 언어로 고정해 글로 옮깁니다. task 는 항상 transcribe 이고, 시각은 기존 TimeMap 으로 조각마다 되돌립니다.
5. 같은 사람의 줄이라도 언어가 바뀌면 새 줄로 씁니다(`merge.join_utterances`).
6. '영어'·'한국어' 고정을 고르면 판별 없이 예전처럼 처리합니다.
7. `처리결과.json` 의 meta 에 트랙별 판별 기술 정보(조각 수, 불확실 수, 나눈 구간 수, 언어별 초)를 남깁니다. 글 내용은 없습니다.

## 3-2. 빌드 산출물(Artifacts) 정리 — `.github/workflows/meeting-recorder-build.yml`, `meeting-recorder-artifact-cleanup.yml`
- exe 묶음 업로드는 `workflow_dispatch`(수동 실행)이거나 기본 브랜치 push 일 때만 합니다(`UPLOAD_BUNDLE`). 그 밖의 실행은 pytest·exe 빌드·exe `--selftest` 까지만 하고, 묶음을 올리지 않은 이유를 로그에 적습니다.
- 중복 제거: 같은 저장소 브랜치의 `pull_request` 실행은 job `if` 로 건너뜁니다(그 브랜치 push 로 이미 돎). 포크 PR 만 pull_request 로 돕니다.
- 보관 기간: 묶음과 selftest 결과 모두 30일 → **7일**.
- 정리 작업(새 워크플로):
  - 매주 월요일 03:17 UTC + 수동 실행(`dry_run` 입력으로 목록만 보기 가능). 권한은 `actions: write` 만.
  - 대상은 이름이 정확히 `MeetingRecorder-windows` 이고 만료되지 않은 아티팩트뿐입니다. 만든 시각 순으로 **최신 2개는 남기고** 나머지를 지웁니다.
- 검사: actionlint 1.7.12 로 두 파일 모두 오류 없음. 실제 GitHub 실행은 확인하지 못했습니다.
- README 1절 내려받기 안내를 바꿨습니다: main 또는 수동 실행에서만 묶음이 있음, 7일·최신 2개, Run workflow 방법.
