# R3 계획서 — 영어가 한국어로 적히는 문제, 빌드 산출물 정리

작성: 총괄, 2026-11-24

## 1. 사용자 보고(R2 exe, 윈도우 회사 PC 실기기)
- **녹음은 잘 된다**(실제 장치 녹음 첫 확인). 
- 기록에서 영어로 말한 부분이 영어로 적히지 않고 한국어로 번역되어 적힌다. 한국어는 한글로, 영어는 영어로 적혀야 한다.
- 범위 확정: 이 프로그램은 **녹음과 대화록**만 되면 된다. 기록이 아주 세밀할 필요는 없다.

## 2. 총괄의 원인 추정(미확인)
`transcribe_file` 은 말소리 구간을 묶음(pack)으로 이어 붙여 `transcribe_window` 에 넣고, 언어는 묶음마다 한 번(앞 30초 기준) 정한다. 한 묶음에 한국어와 영어가 섞이면 먼저 판별된 언어가 묶음 전체에 강제되고, whisper 는 언어가 한국어로 지정된 영어 음성을 한국어로 옮겨 적는(번역하는) 경향이 있다. 사용자 회의는 주로 영어, 가끔 한국어이고 한 트랙 안에서 언어가 바뀐다.
구현자는 한·영이 섞인 표본으로 먼저 재현해 원인을 확정한다.

## 3. 할 일
### 3-1. 언어를 발언 단위로 판별 (핵심)
- 목표: 한 트랙 안에서 언어가 바뀌어도 영어 발언은 영어로, 한국어 발언은 한글로 적는다. 번역하지 않는다(task 는 항상 transcribe).
- 방법은 구현자가 측정해 고른다. 후보: (a) 말소리 구간(또는 화자 분리 결과의 발언)마다 언어를 판별해 같은 언어끼리만 묶어 처리, (b) faster-whisper 의 구간별 언어 판별 기능(있다면 공식 문서·소스로 동작 단위를 확인), (c) 묶음 길이를 줄이고 묶음 안 언어 혼합을 감지해 다시 나눠 처리. 언어 후보는 영어·한국어로 제한한다.
- 짧은 발언(1~2초)은 판별이 불안정하므로 앞뒤 발언·같은 화자의 언어를 참고하는 등 흔들림을 줄인다.
- 언어 설정 '자동'이 기본. '영어'·'한국어' 고정 선택은 그대로 둔다.
- 처리 시간: 사용자 PC(메모리 7.7GB, 내장 그래픽)에서 쓸 수 있어야 한다. R2 대비 처리 시간 증가를 측정해 적고, 1.5배를 넘으면 더 가벼운 방식을 찾는다. 메모리 최고치도 다시 잰다.
- 검증: 한 트랙 안에서 한국어·영어 발언이 번갈아 나오는 표본(공개 라이선스 음성 또는 합성, 출처 기록, 저장소에는 라이선스가 확실한 것만)으로 수정 전 실패 → 수정 뒤 통과를 보인다. 발언별 언어 정답률과, 영어 발언이 한글로 적힌 건수를 적는다. 자체 시험(`--selftest`)에도 혼합 언어 검사를 넣을 수 있으면 넣는다(용량·시간이 크게 늘지 않는 선).

### 3-2. 빌드 산출물(Artifacts) 정리
- exe 묶음(약 540MB) 업로드는 수동 실행(workflow_dispatch)과 기본 브랜치 push 때만. 그 밖의 push·PR 빌드는 시험과 exe 자체 시험까지만 하고 묶음은 올리지 않는다.
- 같은 커밋에 push 와 pull_request 로 두 번 도는 중복을 없앤다.
- 보관 기간 30일 → 7일.
- 오래된 exe 묶음을 지우는 정리 작업 추가(최신 2개만 남김, 일정은 주 1회 + 수동). 권한은 필요한 최소(actions: write)만.
- README 의 내려받기 안내를 바뀐 방식에 맞춘다.

### 3-3. 감사 이월 경미 건
