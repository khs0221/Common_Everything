# R3 결과 — 영어가 한국어로 적히는 문제, 빌드 산출물 정리

작성: 총괄, 2026-11-24

## 결론
언어를 발언 단위로 판별하도록 바꿔, 혼합 언어 표본에서 영어가 한글로 적히는 건수가 6 → 0, 빠진 발언이 14 → 0 이 됐습니다. 감사 치명 0 / 중요 0 / 보통 1 / 경미 4. 실제 한 사람의 한·영 전환 녹음은 사용자 PC 재시험이 필요합니다.

## 사용자 실기기 확인(R2 exe)
- 실제 장치 녹음 정상(헤드셋 사용). 
- 한국어로 말하다 영어로 바꾸면 영어가 한글로 번역되어 적힘 → 이번 라운드 대상.
- 범위 확정: 녹음과 대화록만. `기록.md`·`Copilot용.txt` 는 둘 다 유지.

## 원인
말소리를 최대 180초씩 묶고 묶음의 앞 30초로 언어를 한 번 정해 끝까지 썼습니다. 한국어로 시작한 묶음 안의 영어가 번역되거나 빠졌습니다.

## 바꾼 것
- 말소리 구간마다 언어 판별(3초 창), 구간 안에서 언어가 확실히 바뀌면 조용한 지점에서 분할, 언어별로 모아 언어를 고정해 글로 옮김. 번역 없음.
- 빌드: exe 묶음 업로드는 수동 실행·기본 브랜치 push 만, PR 중복 실행 제거, 보관 7일, 주 1회 정리(최신 2개 보존).
- E1(사용자 폴더 경로 가리기), E3(시작 실패 시 빈 폴더 정리).

## 측정(컨테이너)
- 혼합 표본 52발언: 언어 정답 29 → 52, 영어→한글 6 → 0, 빠짐 14 → 0.
- 처리 시간: 2트랙 영어 10분 1.06배, 영어 단일 트랙 10분 1.30배(감사자 측정), 혼합 62초 표본 1.54배. 메모리 최고치 약 1.6GB 이하.

## 남은 것
- 사용자 PC 재시험: 한국어 → 영어 전환 발언, 처리 시간.
- R4 후보: N1(짧은 발언의 언어 보정), 작은 마이크 입력에서 발언 누락(음량 자동 맞추기), N3, N2(재연결 시 COM 객체), F12, F7 잔여.
