| 판별 모델 | 혼합 64발언(R3 52 포함) 정답 | 영어→한국어 / 한국어→영어 | 판별 시간(6세트) | 메모리 | 짧은 창의 '확실한데 틀림'(기준 0.6 / 0.7, 1초 창·1.5초 창, 각 약 300개) |
|---|---|---|---|---|---|
| small(이전) | 64/64(52/52) | 0 / 0 | 22.3초 | 625MB | 1·0 / 0·0 |
| tiny | 64/64(52/52) | 0 / 0 | 3.9초 | 228MB | 7·4 / 4·3 |
| **base(채택, 기준 0.7)** | **64/64(52/52)** | **0 / 0** | **6.7초** | 317MB | 3·1 / **2·0** |
| turbo | 52/64(42/52) | 0 / 12 | 47.4초 | 1,805MB | — |

- 혼합 표본 기준(small 과 같거나 1건 이내, 영어→한글 0)은 tiny·base 모두 맞췄습니다.
  - R3 방식은 '확실' 판정은 고치지 않으므로, 짧은 창에서 확실하다고 틀리는 비율이 안전성을 좌우합니다.
  - tiny 는 기준을 0.8 로 올려도 1초 창에서 3건이 남아 쓰지 않았습니다.
  - base 는 기준 0.7 에서 1초 창 2건, 1.5초 이상 0건으로 small(0.6) 에 가까워 채택했습니다.
- 모델별 기준값은 `langid.CONF_BY_MODEL = {"small": 0.6, "base": 0.7}` 입니다.
- 화면의 '처리 품질' 선택을 없앴고, 글로 옮기기는 turbo 하나입니다. 처리 시간 안내만 남겼습니다.
- `models.missing_for`: 판별 모델(base)만 없으면 회의 언어를 영어·한국어로 정해 처리할 수 있게 안내합니다.

### (b) turbo int8 저장본
- 변환 방법:
  - 원본 `openai/whisper-large-v3-turbo`(MIT, 커밋 41f01f3, model.safetensors 해시 542566a4…)를 CTranslate2 4.9.1 의 `TransformersConverter` 로 `quantization="int8"` 저장했습니다.
  - 변환 도구 판은 `requirements-convert.txt` 에 고정했습니다(torch 2.15.0 CPU, transformers 5.24.1).
  - 두 번 변환해 model.bin 해시가 같음(7482f978…)을 확인했습니다(리눅스).
  - CI 는 리눅스 작업(`convert-turbo`)에서 변환하고 결과 해시를 검사합니다. 결과는 운영체제 공용 캐시로 윈도우 빌드에 넘깁니다. 제3자 int8 변환본은 쓰지 않았습니다.
- 변환 전후 출력 비교(같은 표본, 계산은 둘 다 int8): **글자 단위로 같지 않습니다.**

| 표본 | 글자 수 | 다른 글자 | 정확도(전 → 후) |
|---|---|---|---|
| 합성 2트랙 42초 | 762 | 0(같음) | — |
| 영어 217초(FLEURS+합성) | 3,542 | 3 | 단어 오류율 0.039 → 0.040 |
| 한국어 109초(FLEURS) | 713 | 5 | 글자 오류율 0.058 → 0.065 |
| 혼합 언어 62초 | 675 | 13(끝에 "감사합니다." 한 번 덧붙음 포함) | 언어 12/12, 영어→한글 0 → 같음 |
| 용어 문장 146초 | 1,991 | 20 | 용어 적중 37/47 → 38/47 |

  - 이유(추정): 실행 때 양자화는 fp16 가중치를, 변환 때 양자화는 원본 fp16→fp32 경로를 거쳐 스케일 계산 값이 조금 다릅니다.
- 불러오기 시간 3.1~7.8초 → 0.5~0.9초, 메모리 최고치 2,694MB → 2,063MB(같은 처리 5건). 처리 시간 합 213 → 175초.
- 판단:
  - 정확도 차이는 측정 잡음 수준입니다(영어 +0.001, 한국어 +0.007, 용어 +1).
  - 이것 없이는 크기 목표를 맞출 수 없어 int8 저장본을 채택했습니다.
  - 글자 단위 동일은 만족하지 못했으므로 총괄 판단이 필요합니다. 되돌리기는 `mrec/models.py` 의 turbo 항목만 바꾸면 됩니다.

### C1. 윈도우 빌드가 늘 캐시를 못 찾음
- 원인(확인): 실행 45621762980 의 로그에서 같은 커밋인데 캐시 이름이 리눅스 `…b567933b…`, 윈도우 `…1524000d…` 였습니다.
  - 그 커밋의 세 파일(models.py, convert_turbo_int8.py, requirements-convert.txt)을 로컬에서 같은 방식으로 해시했습니다. LF 그대로면 b567933b, 줄 끝을 CRLF 로 바꾸면 1524000d 가 나와 둘 다 일치했습니다.
  - 즉 윈도우 체크아웃이 줄 끝을 CRLF 로 바꿔서 `hashFiles` 값이 달라진 것입니다.
- 고침:
  - `tools/ci_cache_key.py` 를 새로 만들었습니다. 같은 세 파일을 CRLF→LF 로 맞춘 뒤 해시해 `key=mrec-turbo-int8-<32자>` 를 출력하고, `GITHUB_OUTPUT` 에도 직접 씁니다(쉘마다 다른 리디렉션 인코딩을 피함).
  - 두 작업이 모두 이 도구로 이름을 정합니다. 리눅스 작업은 setup-python 을 캐시 단계보다 앞에 둡니다.
  - `.gitattributes` 는 추가하지 않았습니다. 다른 해시(모델 캐시 `mrec-models-…`, pip 캐시)는 같은 운영체제 안에서만 쓰므로 영향이 없습니다.
- 캐시를 못 찾을 때:
  - 윈도우 작업은 '캐시 확인' 단계에서 캐시 이름을 적은 오류를 내고 멈춥니다.
  - 윈도우에서 다시 변환하지 않습니다. 결과 바이트가 리눅스와 같은지 보장할 수 없고, 변환 도구(약 1GB)를 또 받아야 하기 때문입니다.
  - 변환 결과는 리눅스 작업에서 해시를 고정해 검사합니다.
- 첫 실행: 캐시 이름이 바뀌었으므로 리눅스 작업이 한 번 다시 변환합니다(제한 35분).

### I1. 언어 판별 모델: small 로 되돌림

### I2. 끝에 덧붙은 "감사합니다."
- 원인(확인):
  - 혼합 표본의 한국어 묶음이 30.19초라, whisper 의 두 번째 30초 창에는 소리 0.19초와 무음 채움만 들어갑니다.
  - int8 이 그 창에서 "감사합니다."(30.00~30.04초, 낱말 확률 0.39)를 냈습니다.
  - turbo 는 무음 확률(no_speech_prob)이 늘 0.00 이라 whisper 기본 거르기가 듣지 않습니다.
  - fp16 도 같은 현상이 있습니다. 변형 표본 D(한→영 흐름)에서 fp16 도 끝에 "감사합니다." 를 덧붙였습니다(아래 표). int8 만의 문제는 아닙니다.
- 방지 장치(`transcribe.HallucinationGuard`, 모든 묶음에 적용):
  1. 소리 없는 곳의 글
     - 구간이 묶음 소리 끝을 넘어 0.1초 미만만 남으면 버립니다.
     - 구간 소리 크기(RMS)가 묶음 말소리 크기(32ms 창 RMS 의 75번째 백분위)의 10% 미만이어도 버립니다.
  2. 확신 낮은 짧은 글: 4단어 이하이고 첫 낱말 확률 < 0.35, 평균 < 0.6 이면 버립니다.
- 측정: 모든 표본 10개(2트랙 표본, 혼합, 영어 42문장, 한국어 20문장, 용어 40문장, 변형 A~E) + 잡음 창 10개(5종 × 영·한, 말소리 구간 검출 없이 30초 통째).

| 덧붙은 문장(10개 표본 합) | 2(혼합·D "감사합니다.") | **0** | 1(D "감사합니다.") | 0 |
| 잡음 창에서 지어낸 글 | 10/10 | **2/10** | 10/10 | 2/10 |
| 발언 수(10개 표본) | 11·8·20·15·5·11·11·8·6·3 | **같음** | 11·8·20·15·6·11·12·8·6·3 | 같음 |
| 영어 WER / 한국어 CER | 0.040 / 0.065 | **같음** | 0.039 / 0.058 | 같음 |

- 방지 장치는 정상 발언을 하나도 버리지 않았습니다. 켜고 끈 출력이 덧붙은 문장 말고는 같습니다.
- 기준과의 여유(int8, 실제 표본 구간 171개):
  - 버린 것은 두 "감사합니다."(소리 0.04초·0.06초)뿐입니다.
  - 남은 구간의 최소 길이는 1.36초(기준 0.1), 최소 소리 크기 비는 0.33(기준 0.1)입니다.
  - 4단어 이하 구간은 2개였고 첫 낱말 확률은 0.84 이상(기준 0.35)이었습니다.
- 남은 잡음 2건:
  - 웅웅거림+딸깍 소리(한국어)의 "다음 영상에서 만나요."(평균 0.64)
  - 거의 무음(영어)의 "Thank you."(평균 0.65)
  - 실제 처리에서는 말소리 구간 검출(VAD)이 이런 구간을 대부분 미리 뺍니다(추정, 잡음 창 시험은 VAD 를 건너뜀).
