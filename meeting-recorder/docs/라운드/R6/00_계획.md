# R6 계획서 — 묶음 크기 줄이기, 더 정확하고 빠른 모델 검토

작성: 총괄, 2026-11-25

## 1. 사용자 요청
- '빠름' 모드는 쓰지 않을 것 같다. 정확(turbo)만 넣어 내려받는 묶음 용량을 줄일 수 있는가.
- 지금 쓰는 모델보다 인식률이 좋고 빠른 모델이 있는가.
- 회의는 주로 영어, 가끔 한국어. 한 사람이 한국어와 영어를 오가는 발언이 있다(R3 에서 해결한 문제를 되돌리면 안 됨).

## 2. 할 일
### 2-1. 묶음 크기 줄이기
현재 약 2.03GB(압축 후). 구성: turbo 약 1.6GB, small 약 0.48GB, 그 밖.
- (a) '빠름' 품질 선택을 화면에서 없앤다. 단, small 은 지금 발언 단위 언어 판별에도 쓰인다(R4 측정: small 64/64·20초, turbo 56/64·54초). small 을 빼려면 판별을 무엇으로 할지 측정으로 정한다. 후보: whisper tiny·base(다국어) 판별, turbo 판별. 기준: R3 혼합 표본(52발언)과 R4 표본(64발언)에서 판별 정확도가 small 과 같거나 1건 이내 차이이고 영어→한글 0건 유지. 기준을 못 맞추면 small 을 판별 전용으로 남긴다(화면의 '빠름'만 없앰).
- (b) turbo 모델을 8비트(int8)로 저장한 변환본으로 바꿔 파일 크기를 줄일 수 있는지 확인한다. 지금도 실행 때 int8 로 계산하므로 결과가 같아야 한다. 확인할 것: 변환 방법(CTranslate2 변환 도구로 직접 변환 — CI 에서 재현 가능해야 함 — 또는 신뢰할 수 있는 배포처의 변환본), 변환 전후 출력이 같은지(같은 표본에서 글자 단위 비교), 불러오는 시간·메모리, 라이선스·해시 고정. 제3자가 올린 변환본은 출처 신뢰성을 따져 보고, 불확실하면 직접 변환한다.
- 목표: 압축 후 1.2GB 이하. 못 미치면 어디까지 줄었는지와 이유를 적는다.

### 2-2. 더 정확하고 빠른 모델 검토(측정으로 결정)
총괄의 사전 지식(불확실, 반드시 공식 자료와 실제 실행으로 확인):
- 영어 전용으로는 whisper 계열보다 정확하고 CPU 에서 훨씬 빠르다고 알려진 모델이 있다(예: NVIDIA Parakeet TDT 0.6b v2, sherpa-onnx 로 실행 가능하다고 알고 있음). 한국어는 지원하지 않는다.
- 한국어를 포함한 다국어 후보(예: SenseVoice)는 영어 정확도가 turbo 보다 낮을 수 있다.
- 따라서 유력한 구성은 "영어 발언은 영어 전용 모델, 한국어 발언은 turbo" 혼합이다. 발언 단위 언어 판별(R3)이 이미 있어 구조상 가능하다.
조사·측정
1. 후보를 공식 자료(모델 카드, 공개 순위표, sherpa-onnx 문서)로 확인해 2~3개로 추린다. 라이선스(회사 사용 가능 여부), 파일 크기, 구두점·대소문자 출력 여부, 단어 시각 제공 여부, 용어 힌트(hotwords) 지원 여부를 표로 만든다.
2. 추린 후보를 실제로 돌려 turbo 와 비교한다: 영어 10분, 용어 표본(47개 용어), 혼합 표본, 잡음 구간. 항목: 단어 오류율, 용어 적중, 처리 시간, 메모리 최고치, 말하지 않은 내용 삽입 여부.
3. 채택 규칙: 영어 전용 후보가 turbo 대비 ① 영어 단어 오류율이 같거나 낮고 ② 용어 적중이 2개 이내로만 낮거나 같거나 높고 ③ 영어 처리 시간이 0.7배 이하이며 ④ 메모리 최고치 4GB 이하이고 ⑤ 화자 붙이기에 필요한 시각 정보가 충분하면, 영어 발언에 그 모델을 쓰고 한국어 발언은 turbo 를 쓴다. 하나라도 어긋나면 채택하지 않고 turbo 를 유지한다. 채택 시 묶음 크기 목표(1.2GB)를 넘기면 넘긴 크기와 얻는 이득을 함께 보고한다(총괄이 사용자에게 선택을 묻는다).
4. 혼합 구성의 위험을 확인한다: 언어 판별이 틀린 발언이 영어 전용 모델로 가면 한국어가 엉뚱한 영어로 적힌다. 판별 확신이 낮은 발언은 turbo 로 보내는 등 안전장치를 두고, 혼합 표본에서 오기 0건을 확인한다.

### 2-3. 이월 건
- CI '모델 받기' 단계에 시간 제한과 재시도(2026-11-25 기본 브랜치 빌드가 이 단계에서 16분 멈춤).
- R5 N1: 실패한 장치 열기의 자원 정리, 재연결 때는 마지막으로 성공한 방법부터 시도.
- R4 N1: 용어 끼어듦 검사 보강(쉼표 없는 용어 나열, 1~2단어 삽입).

## 3. 하지 않는 것
녹음 이어하기·일시정지(사용자 결정 대기), 프로그램 안 요약.

## 4. 제약
R1 계획서 5절과 같다. 공개 저장소이므로 문서·주석에 사용자 환경·회사를 추정할 서술을 넣지 않는다. 실행 중 외부 접속 없음(모델은 빌드 때 받아 동봉, 해시 고정). 사용자 PC 는 메모리 약 8GB·CPU 전용으로 본다(R5 진단 정보 기준).

## 5. 완료 기준
- pytest 통과, 윈도우 빌드와 `--selftest` 성공.
- 크기 표(변경 전·후), 언어 판별 모델 비교표, 후보 모델 비교표와 채택 여부.
- R3 혼합 표본에서 영어→한글 0건·누락 0건 유지.
