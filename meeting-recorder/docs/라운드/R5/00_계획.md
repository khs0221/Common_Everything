# R5 계획서 — 특정 마이크(USB 헤드셋)를 열지 못하는 문제

작성: 총괄, 2026-11-25

## 1. 사용자 보고(R4 exe, 실기기)
- 내 마이크를 '자동'(윈도우 기본 = 노트북 내장 마이크 배열)으로 두면 녹음이 된다.
- 내 마이크를 USB 헤드셋 마이크로 고르면 "녹음을 시작하지 못했습니다 … 장치를 열 수 없습니다" 가 뜬다. 같은 헤드셋의 이어폰 쪽(스피커 루프백)은 정상으로 열린다.
- [오류 내용 복사] 요지:
  - 윈도우 11, 로컬 세션
  - 마지막으로 연 장치: 마이크=내장 마이크, 스피커=USB 헤드셋 이어폰
  - `RuntimeError: 장치를 열 수 없습니다: ` ← 콜론 뒤가 비어 있음
  - 경로: gui.start_recording → recorder.start → _run → _open → devices.open_microphone → _open_mic → `_SoundcardSource.__init__`(devices.py:141)

## 2. 총괄 분석
- `_SoundcardSource.__init__` 은 16000/48000/44100 세 주파수로 `mic_obj.recorder(samplerate=sr, channels=1, blocksize=…)` 와 `__enter__()` 를 시도하고, 모두 실패하면 마지막 예외의 `str()` 만 붙여 다시 던진다. 메시지가 비었다는 것은 마지막 예외의 문자열이 빈 예외(예: 인자 없는 AssertionError·MemoryError·NotImplementedError·IndexError 류, 또는 메시지 없이 만든 예외)라는 뜻이다. soundcard 의 `check_error` 가 만든 예외라면 `Error 0x…` 문구가 있었을 것이다.
- 진단 결함: 예외 종류와 주파수별 실패 내용이 남지 않아 원인을 알 수 없다. 이것부터 고쳐야 한다.
- 원인 후보(미확인): 모노 USB 헤드셋 마이크에서 `channels=1` 처리 또는 버퍼 길이(blocksize) 관련 경로, 장치가 보고하는 형식과 요청 형식의 불일치. CI 에는 이 장치가 없어 재현할 수 없으므로, soundcard 0.4.6 소스를 읽어 "문자열이 빈 예외"가 나올 수 있는 지점을 모두 찾아 대응한다.

## 3. 할 일
1. **진단 보강(필수)**: 장치 열기 실패 시 시도한 조합마다 (주파수, 채널, 버퍼 길이, 예외 종류, repr, HRESULT 가 있으면 그 값)을 모아 오류 메시지·로그·[오류 내용 복사]에 넣는다. soundcard 가 알려 주는 장치 속성(채널 수 등 얻을 수 있는 것)도 넣는다. 예외를 다시 던질 때 원인 예외를 연결(`from`)한다.
2. **열기 방식 넓히기**: 지금 조합이 실패하면 다른 조합으로 물러난다. 예: 채널을 장치 기본값(None)으로 열고 프로그램에서 모노로 합치기, 장치 기본 주파수로 열고 16kHz 로 변환, 버퍼 길이 기본값. 소스로 확인한 실패 지점을 피하는 조합을 앞에 둔다. 어떤 조합으로 열렸는지 로그에 남긴다. 기존에 되던 장치(내장 마이크 배열, 루프백)의 동작·시각 맞춤(F3)·리샘플러 경로가 달라지지 않게 한다.
3. **시험**: 가짜 장치로 "특정 조합에서만 문자열이 빈 예외를 던지는 장치"를 흉내 내, 물러나기와 진단 내용이 맞는지 시험한다. 자체 시험(`--selftest`)의 장치 경로 검사에도, 장치가 있으면 목록의 각 마이크를 실제로 열어 0.2초 읽어 보고 조합·결과를 selftest.json 에 적는 항목을 추가한다(장치 0개인 CI 에서는 참고).
4. **장치 점검 버튼(작음)**: 화면에 [장치 점검]을 두어, 녹음하지 않고도 고른 마이크·스피커를 1초 열어 입력 레벨과 열린 조합을 보여 준다. 실패하면 3-1 의 진단을 그대로 보여 준다. 사용자가 회의 전에 확인하는 용도.
5. 이월 경미 건(작음): E1(UTF-16 용어 파일 읽기, 못 읽으면 화면에 '읽지 못함'으로 표시), E2(README 내려받기 크기 정정, 한 모델만 없을 때 다른 품질은 쓸 수 있게).

## 4. 하지 않는 것
녹음 이어하기·일시정지(사용자 결정 대기), 용어 끼어듦 검사 보강(R4 N1, 다음 라운드).

## 5. 제약
R1 계획서 5절과 같다. 저장소가 공개 상태이므로 문서·주석에 사용자 환경·장치 모델명·회사를 추정할 서술을 넣지 않는다(장치는 'USB 헤드셋', '내장 마이크' 로만). 실기기 재현이 불가능하므로 "소스로 확인한 것 / 추정 / 미검증"을 구분해 적는다.

## 6. 완료 기준
- pytest 통과, 윈도우 빌드와 `--selftest` 성공.
- 빈 문자열 예외 장치를 흉내 낸 시험에서 다른 조합으로 열리고, 모두 실패해도 진단에 조합별 예외 종류가 남는다.
- soundcard 소스에서 찾은 "문자열이 빈 예외" 지점 목록과 각 대응.
