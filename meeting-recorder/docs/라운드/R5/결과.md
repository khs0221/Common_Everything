# R5 결과 — 특정 마이크(USB 헤드셋)를 열지 못하는 문제

작성: 총괄, 2026-11-25

## 결론
열기 방식을 3단계로 넓히고 진단을 보강했습니다. 감사 치명 0 / 중요 0 / 보통 2 / 경미 3. 실제 USB 헤드셋 마이크에서 열리는지는 사용자 재시험으로 확인합니다.

## 원인(소스로 좁힌 추정)
soundcard 0.4.6 이 장치 믹스 형식을 assert 로 검사하고, 맞지 않으면 메시지 없이 실패합니다. 주파수와 무관해 세 번 모두 같은 지점에서 실패했습니다.

## 바꾼 것
- 열기 순서: 기존 조합(동작 불변) → 형식을 직접 만들어 열기 → soundcard 기본값.
- 진단: 조합별 예외 종류·repr·HRESULT·실패 위치, 장치 믹스 형식을 오류 칸·[오류 내용 복사]·로그에 기록.
- [장치 점검] 버튼, 자체 시험의 실제 장치 열기 항목.
- UTF-16 용어 파일 읽기, 한 모델만 없을 때 다른 품질 사용 가능, README 크기 정정.

## 검증
pytest 화면 없는 환경 106 통과 + 8 실행 안 함(감사자 독립 실행과 일치). 윈도우 빌드는 아래 PR 에서 확인.

## 남은 것
- 사용자 재시험: USB 헤드셋 마이크로 [장치 점검]과 녹음, 내 목소리가 깨지지 않는지.
- R6 후보: N1(실패한 열기 정리·재연결 시 성공한 방법 우선), N2(PCM 형식 장치의 소리 깨짐 검사), R4 N1(용어 끼어듦 검사), 녹음 이어하기·일시정지(사용자 결정 대기).
