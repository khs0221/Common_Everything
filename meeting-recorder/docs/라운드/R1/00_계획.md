# 회의 녹음·기록 프로그램 — 라운드 R1 계획서 (골조)

작성: 총괄, 2026-11-23

## 1. 목적
사용자가 Teams 등 화상회의(고객이 여는 회의 포함)를 자기 PC에서 녹음하고, 발언자가 구분된 글 기록을 만든다.
요약은 회사가 승인한 Microsoft Copilot 에 사용자가 직접 붙여 넣어 만든다. R1 은 **작동하는 골조**까지다.

## 2. 사용자·환경 (확정 사실)
- 비개발자, 윈도우 회사 PC. 메모리 7.7GB, GPU 는 인텔 Iris Xe(내장) → **CPU 전용, 저메모리 전제**.
- 회의 언어: 주로 영어, 가끔 한국어.
- 회의 내용은 사내에서만 쓴다 → **프로그램은 실행 중 인터넷에 접속하지 않는다**(모델 포함 전부 동봉).
- 사용자는 파이썬을 설치하지 않는다. 압축을 풀고 exe 를 실행하는 것이 전부여야 한다.

## 3. 범위 (R1 에서 만드는 것)
1. **녹음**: [녹음 시작]/[중지]. 마이크(나)와 스피커 출력(상대방, WASAPI 루프백)을 **별도 트랙**으로 저장.
   - 두 트랙의 시간축이 어긋나지 않아야 한다(루프백은 무음 구간에 데이터가 안 올 수 있음 → 무음 채움 등으로 처리).
   - 장치는 윈도우 기본 장치를 기본값으로 하고, 창에서 바꿀 수 있게 한다.
   - 긴 회의(2시간)에도 메모리가 늘지 않게 디스크에 흘려 쓴다. 비정상 종료 시에도 그때까지의 녹음이 남아야 한다.
2. **글로 옮기기**: PC 안에서 처리. 후보 faster-whisper(CPU, int8). 기본 모델은 8GB·내장 그래픽에서 실용적인 크기(후보 small, 다국어)로 하고 근거를 changes.md 에 적는다. 언어 선택: 자동/영어/한국어.
3. **발언자 구분**: 마이크 트랙 = "나"(확정). 스피커 트랙은 PC 안에서 화자 분리해 "참석자 1, 2…".
   - 후보: sherpa-onnx 의 오프라인 화자 분리(onnxruntime, torch 불필요). **실제 API·모델·라이선스를 공식 문서로 확인하고 실행해 본 뒤 채택**한다. 안 되면 대안과 이유를 적는다.
   - torch 기반(pyannote 원본)은 exe 크기·메모리·토큰 게이트 때문에 피한다.
4. **결과물** (회의마다 폴더 1개: `회의_YYYYMMDD_HHMM/`)
   - 녹음 파일 2개, `기록.md`(시각·발언자·내용, 시간순 병합), `Copilot용.txt`(요약 지시문 + 기록 전문: 발언자별 주요 발언, 결정 사항, 할 일, 미결 사항을 요청).
   - 참석자 이름 지정: 처리 뒤 "참석자 N"마다 대표 발언 1~2개를 보여 주고 이름을 입력받아 결과물을 다시 쓴다.
5. **화면**: tkinter 한 창. 한국어. 녹음 시작/중지, 경과 시간, 입력 레벨 표시(두 트랙 각각 — 녹음이 되고 있는지 눈으로 확인), 언어 선택, 처리 진행률, 결과 폴더 열기, 기존 녹음 파일 다시 처리.
6. **배포**: PyInstaller(onedir) + 모델 동봉 zip 을 GitHub Actions `windows-latest` 에서 만들어 artifact 로 올린다. 워크플로는 저장소 루트 `.github/workflows/meeting-recorder-build.yml`(경로 필터 `meeting-recorder/**`, workflow_dispatch 포함). exe 에 `--selftest`(모델 로드 + 동봉 표본 음성 글 옮기기·화자 분리, 장치 불필요)를 넣고 CI 에서 실행한다.

## 4. 범위 밖 (R1 에서 하지 않는 것)
- 프로그램 안에서 요약하기, 외부 AI 호출, 자동 시작·상시 녹음, 화면 녹화, 회의 자동 감지.

## 5. 제약·지킬 것
- 코드 위치: `meeting-recorder/` 아래만. 저장소의 다른 폴더는 건드리지 않는다.
- 브랜치: `claude/wizardly-lovelace-ojns73` 만 push. main·강제 push 금지. PR·병합은 총괄이 한다.
- 실행 시 네트워크 접속 없음(모델은 빌드 때 받아 동봉). 텔레메트리·자동 업데이트 없음.
- 녹음·기록 파일은 저장소에 넣지 않는다(.gitignore). 시험용 음성은 공개 라이선스 또는 합성음만, 출처를 적는다.
- 쓰는 라이브러리·모델의 라이선스를 `docs/라이선스.md` 에 표로 적는다(회사 PC 에서 쓰므로 상업적 사용 가능 여부 포함).
- 이 컨테이너(리눅스)에는 소리 장치가 없다. 녹음 부분은 장치 없이 검증할 수 있는 구조(장치 계층 분리 + 가짜 입력 테스트)로 만들고, **검증하지 못한 부분을 숨기지 말고 명시**한다.
- 테스트: `python -m pytest -q` (외부 접속 없음, 모델이 없으면 해당 테스트는 skip 이 아니라 별도 표시로 구분).
- 모델을 이 컨테이너에서 받을 수 없으면(네트워크 정책) 우회하지 말고 '차단'으로 보고한다.

## 6. 산출물
- 코드·테스트·워크플로, `meeting-recorder/README.md`(사용자용: 내려받기 → 압축 풀기 → 실행 → 첫 시험 1분, 클릭 단계. 헤드셋 권장 이유 포함: 스피커를 쓰면 마이크에 상대방 소리가 들어가 중복됨)
- `docs/라운드/R1/changes.md`: 한 일, 채택·기각한 기술과 근거, 측정값(표본 음성 처리 시간·메모리 최고치), **검증한 것 / 못 한 것**, 사용자 PC 에서 확인할 항목.
- `docs/라운드/R1/진행.md`: 중단 시 이어갈 수 있게 단계별 상태.

## 7. 완료 기준
- pytest 통과, CI 에서 exe 빌드와 `--selftest` 성공.
- 표본 음성(2인 이상 대화)으로 기록.md 와 Copilot용.txt 가 실제로 생성됨(컨테이너 또는 CI).
- 8GB PC 에서 처리 중 메모리 최고치 추정이 4GB 이하라는 근거.

## 8. 심각도 (감사용)
- 치명: 녹음 유실·트랙 어긋남, 실행 중 외부 전송, 회의 내용이 저장소·로그로 새는 경로, exe 가 실행되지 않음.
- 중요: 장시간 녹음 시 메모리 증가, 화자 표시 오류를 만드는 병합 버그, 라이선스 위반, README 대로 따라 했을 때 막히는 단계.
- 보통·경미: 그 외.
